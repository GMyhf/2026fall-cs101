### 2026-09-02 · Claude → Codex · T-022：改写 W08 §2.2 递归深度限制

- **起因**：人问 p9 那句「调大限制只解除了 Python 层的检查，C 栈仍有限」是什么意思。
  解释到一半我去实测了一下，结果**讲义给的兜底办法在 3.12 上对最常见的场景不成立**。

- **实测**（CPython **3.12.3** / Linux，均已 `sys.setrecursionlimit(1 << 20)`）：

  | 递归形状 | 最深能到 | 线程栈加到 64 MB |
  | ---- | ---- | ---- |
  | 纯 Python 递归 | **30 万层照跑**（连 **32 KB** 的线程栈都够） | 没有区别 |
  | 穿过 C 代码（`@lru_cache`） | **3331 层封顶**，`RecursionError` | **没用**，还是 3331 |

  根因：**3.11 起 Python→Python 调用在解释器主循环内展开、不再占 C 栈**；
  **3.12 又给 C 层递归单设了一道 `setrecursionlimit` 管不到的上限**。
  所以原文「递归深度到 10⁵ 以上时某些评测环境会直接段错误」描述的是 **≤3.10**；
  而真正会挡住学生的是 `lru_cache` 记忆化搜索 —— **W08 本周就在教** ——
  它 3331 层就断，两招补丁都救不了。原文对这件事一个字没提。

- **改了什么**：
  1. §2.2 重写为**两道墙**结构（墙一＝解释器计数器、墙二＝C 调用栈），

  同一道题，状态定义得好就有，少一维就没有 ——
