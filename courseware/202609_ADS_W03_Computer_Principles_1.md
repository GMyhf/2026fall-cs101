# 1 计算机科学是什么

## 1.1 一个常见的误解

> **计算机科学不是关于计算机的科学**，正如天文学不是关于望远镜的科学。

计算机科学研究的是**什么问题可以被计算、怎样高效地计算、计算的代价是多少**。
计算机只是执行这些计算的机器。

## 1.2 学科体系

| 层次 | 关注 | 本课涉及 |
| ---- | ---- | ---- |
| 理论 | 可计算性、复杂性、算法 | 图灵机、大 O、算法设计 |
| 系统 | 体系结构、操作系统、网络、编译 | 冯·诺依曼结构、虚拟地址空间、进程 |
| 应用 | 数据库、图形学、人工智能 | AI 素养、知识图谱、神经网络 |

## 1.3 抽象：计算机科学最核心的工具

同一件事，在不同层次上看到的是不同的东西：

```
   应用层     print("hello")
      ↓
   语言层     Python 字节码
      ↓
   运行层     CPython 解释器（C 程序）
      ↓
   系统层     系统调用 write()
      ↓
   硬件层     CPU 指令、内存读写、电压高低
```

**你不需要同时想所有层**——这正是抽象的价值。但**知道下一层存在**，能让你在出错时知道往哪儿看。

# 2 图灵机与可计算性

## 2.1 模型

1936 年，Alan Turing 提出了一个极简的计算模型：

```
    ... │ 1 │ 0 │ 1 │ 1 │ 0 │ ...      ← 无限长的纸带，每格一个符号
              ▲
              │ 读写头（可左移 / 右移 / 读 / 写）
         ┌────┴────┐
         │  状态机  │  当前状态 + 读到的符号 → 写什么、往哪移、转到哪个状态
         └─────────┘
```

一个图灵机由**五元组转移规则**定义：

```
(当前状态, 读到的符号) → (写入的符号, 移动方向, 下一状态)
```

## 2.2 为什么它重要

- **丘奇—图灵论题**：任何"直觉上可计算"的函数，都能被图灵机计算。
  你的 Python 程序、C++ 程序，能算的东西不比图灵机多。
- **停机问题不可判定**：不存在一个程序，能对任意程序 + 任意输入判断它是否会停机。
  这是计算的**根本边界**——不是"我们还没想到办法"，而是**证明了不可能**。

## 2.3 用 Python 实现一台图灵机

下面这台机器把纸带上的二进制数**加一**：

```python
def turing_machine(tape, rules, start="q0", halt="halt", blank="_"):
    """通用图灵机模拟器。

    tape:  初始纸带字符串
    rules: {(state, symbol): (write, move, next_state)}，move ∈ {'L','R','N'}
    返回停机时的纸带内容（去掉两端空白）。
    """
    cells = dict(enumerate(tape))
    head, state, steps = len(tape) - 1, start, 0
    while state != halt and steps < 100000:
        sym = cells.get(head, blank)
        if (state, sym) not in rules:
            break
        write, move, state = rules[(state, sym)]
        cells[head] = write
        head += {"L": -1, "R": 1, "N": 0}[move]
        steps += 1
    lo, hi = min(cells), max(cells)
    return ''.join(cells.get(i, blank) for i in range(lo, hi + 1)).strip(blank)


# 二进制加一：从最低位向左扫，遇 1 变 0 继续借位，遇 0 或空白变 1 停机
INCREMENT = {
    ("q0", "1"): ("0", "L", "q0"),
    ("q0", "0"): ("1", "N", "halt"),
    ("q0", "_"): ("1", "N", "halt"),
}

for x in ["1011", "111", "0"]:
    print(x, "->", turing_machine(x, INCREMENT))
# 1011 -> 1100
# 111  -> 1000
# 0    -> 1
```

> 这段代码值得亲手跑一遍：**一台"计算机"的本质，就是这三十行**。

# 3 冯·诺依曼结构

## 3.1 五大部件

```
        ┌──────────────────────────────────────┐
        │              存储器 Memory            │  ← 程序和数据放在一起
        └───────┬──────────────────────┬───────┘
                │                      │
        ┌───────▼───────┐      ┌───────▼───────┐
        │  运算器 ALU    │      │  控制器 CU     │
        └───────────────┘      └───────────────┘
                     └──── CPU ────┘
        ┌───────────────┐      ┌───────────────┐
        │  输入设备      │      │  输出设备      │
        └───────────────┘      └───────────────┘
```

**核心思想：存储程序（stored program）**——程序本身也是数据，和数据一起放在存储器里。
这就是为什么同一台机器能跑不同的程序，而不需要重新接线。

## 3.2 指令周期

```
取指 Fetch → 译码 Decode → 执行 Execute → 写回 Write Back
      ↑                                          │
      └──────────────────────────────────────────┘
```

**冯·诺依曼瓶颈**：CPU 和内存之间的总线是共享的，取指令和取数据要排队。
现代 CPU 用多级缓存缓解它——这也是"访问连续内存比跳着访问快"的根源。

## 3.3 存储层次

| 层级 | 典型容量 | 访问时间 | 相对代价 |
| ---- | ---- | ---- | ---- |
| 寄存器 | 几百字节 | < 1 ns | 1 |
| L1 缓存 | 32–64 KB | ~1 ns | ~3 |
| L2 / L3 缓存 | 几 MB–几十 MB | ~10 ns | ~15 |
| 内存 DRAM | 8–64 GB | ~100 ns | ~200 |
| SSD | 几百 GB–几 TB | ~100 μs | ~10⁵ |
| 机械硬盘 | 几 TB | ~10 ms | ~10⁷ |

**从上到下：容量越大、速度越慢、单价越低。**

> 这张表能解释很多"为什么这么慢"：一次内存访问 ≈ 100 次寄存器访问，
> 一次磁盘访问 ≈ 10 万次内存访问。第 6 周讲矩阵时会看到按行遍历比按列遍历快的实例。

# 4 数据的二进制表示

## 4.1 进制

| 进制 | 前缀 | 数字 | 用途 |
| ---- | ---- | ---- | ---- |
| 二进制 | `0b` | 0–1 | 机器本身 |
| 八进制 | `0o` | 0–7 | Unix 权限 |
| 十进制 | 无 | 0–9 | 人 |
| 十六进制 | `0x` | 0–9 A–F | 内存地址、颜色、字节转储 |

```python
n = 233
print(bin(n), oct(n), hex(n))        # 0b11101001 0o351 0xe9
print(int("11101001", 2))            # 233
print(int("e9", 16))                 # 233
print(f"{n:b} {n:o} {n:x} {n:08b}")  # 11101001 351 e9 11101001
```

**手工转换**：除基取余，余数**逆序**读。

```
233 ÷ 2 = 116 … 1   ↑
116 ÷ 2 =  58 … 0   │
 58 ÷ 2 =  29 … 0   │  逆序读：11101001
 29 ÷ 2 =  14 … 1   │
 14 ÷ 2 =   7 … 0   │
  7 ÷ 2 =   3 … 1   │
  3 ÷ 2 =   1 … 1   │
  1 ÷ 2 =   0 … 1   │
```

**E02734: 十进制到八进制**，<http://cs101.openjudge.cn/practice/02734/>

```python
n = int(input())
print(oct(n)[2:] if n else 0)
```

## 4.2 有符号整数：原码、反码、补码

以 8 位为例表示 −5：

| 表示法 | −5 的编码 | 问题 |
| ---- | ---- | ---- |
| 原码 | `1000 0101` | 有 +0 和 −0 两个零；加减法要判符号 |
| 反码 | `1111 1010` | 仍有两个零 |
| **补码** | `1111 1011` | **零唯一；减法 = 加负数，硬件只需一套加法器** |

**补码的求法**：正数不变；负数 = 取反后加一。

```python
def to_twos_complement(x, bits=8):
    return format(x & ((1 << bits) - 1), f'0{bits}b')

print(to_twos_complement(5))    # 00000101
print(to_twos_complement(-5))   # 11111011
print(to_twos_complement(-1))   # 11111111
```

n 位补码的表示范围是 **−2ⁿ⁻¹ ~ 2ⁿ⁻¹−1**（8 位：−128 ~ 127），**负数比正数多一个**。

> Python 的 `int` 是任意精度的，不会溢出；但 C/C++ 的 `int` 是 32 位，
> `2147483647 + 1` 会变成 `-2147483648`。用 C++ 做题时，这是最常见的 WA 来源。

## 4.3 位运算

| 运算 | 符号 | 例子 | 结果 |
| ---- | ---- | ---- | ---- |
| 与 | `&` | `6 & 3` | `2`（110 & 011 = 010） |
| 或 | `\|` | `6 \| 3` | `7` |
| 异或 | `^` | `6 ^ 3` | `5` |
| 取反 | `~` | `~6` | `-7` |
| 左移 | `<<` | `1 << 10` | `1024` |
| 右移 | `>>` | `1024 >> 3` | `128` |

三个常用技巧：

```python
n = 12
print(n & 1)              # 判奇偶：0 偶 1 奇
print(n & (n - 1))        # 把最低位的 1 清零 -> 8
print(bin(n).count('1'))  # 统计 1 的个数（popcount）-> 2

# n & (n-1) == 0 判断是否 2 的幂（n > 0）
print(all((x & (x - 1)) == 0 for x in [1, 2, 4, 8, 16]))   # True

# 异或的两个性质：a^a=0, a^0=a  → 找出只出现一次的数
nums = [4, 1, 2, 1, 2]
r = 0
for v in nums:
    r ^= v
print(r)                  # 4
```

最后一个就是 LeetCode 136《只出现一次的数字》的标准解，<https://leetcode.cn/problems/single-number/>。

## 4.4 浮点数与精度陷阱

IEEE 754 双精度（64 位）：

```
 ┌─┬───────────┬────────────────────────────────────────────┐
 │S│  指数 11  │              尾数 52 位                     │
 └─┴───────────┴────────────────────────────────────────────┘
   值 = (-1)^S × 1.尾数 × 2^(指数-1023)
```

因为尾数是**二进制**小数，十进制的 0.1 无法精确表示（就像十进制无法精确表示 1/3）：

```python
print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False
print(f"{0.1:.20f}")        # 0.10000000000000000555
```

**正确的比较方式**：

```python
import math
print(math.isclose(0.1 + 0.2, 0.3))                  # True
print(abs((0.1 + 0.2) - 0.3) < 1e-9)                 # True

from decimal import Decimal
print(Decimal('0.1') + Decimal('0.2'))               # 0.3   —— 十进制精确运算
```

> **本课的硬规则**：浮点数**永远不要用 `==` 比较**；能用整数就用整数。
> 判断"能否整除"用 `a % b == 0`，不要用 `a / b == a // b`。

无穷大的写法：

```python
INF = float('inf')
print(INF > 10**100)        # True
print(-INF < 0)             # True
```

第 10 周起做 DP 与最短路时，`float('inf')` 是初始化的标准写法。

# 5 字符编码

## 5.1 ASCII

7 位，128 个字符。必须记住的几个：

| 字符 | 十进制 | 说明 |
| ---- | ---- | ---- |
| `'0'` | 48 | 数字起点 |
| `'A'` | 65 | 大写起点 |
| `'a'` | 97 | 小写起点 |
| 空格 | 32 | |

**大小写相差 32**（正好是 `1 << 5`），所以：

```python
print(ord('A'), chr(97))        # 65 a
print(chr(ord('a') - 32))       # A
print(chr(ord('A') | 32))       # a   —— 位或置位，转小写
print(ord('7') - ord('0'))      # 7   —— 数字字符转数值
```

## 5.2 Unicode 与 UTF-8

- **Unicode** 是**字符集**：给世界上每个字符一个码点，如 `U+4E2D` 是"中"。
- **UTF-8** 是**编码方式**：把码点变成字节序列，ASCII 字符占 1 字节，汉字通常占 3 字节。

```python
s = "中A"
print(len(s))                    # 2  —— Python 字符串按字符计数
b = s.encode('utf-8')
print(b, len(b))                 # b'\xe4\xb8\xadA' 4  —— 字节数不同
print(b.decode('utf-8'))         # 中A
print(hex(ord('中')))            # 0x4e2d
```

**乱码的本质**：用 A 编码存的字节，拿 B 编码去解。文件读写时显式指定编码：

```python
with open('data.txt', encoding='utf-8') as f:
    text = f.read()
```

# 8 小结

1. 计算机科学研究的是**计算本身**，计算机只是载体；**抽象**是它最核心的工具。
2. 图灵机划定了可计算的边界；**停机问题不可判定**是证明了的不可能，不是暂时做不到。
3. 冯·诺依曼结构的核心是**存储程序**；存储层次解释了绝大多数"为什么这么慢"。
4. 整数用**补码**（零唯一、减法即加法）；浮点数是二进制近似，**永远不要用 `==` 比较**。
5. ASCII 中 `'0'=48, 'A'=65, 'a'=97`，大小写差 32；Unicode 是字符集，UTF-8 是编码方式。
