## P4｜经典陷阱：默认参数是可变对象

先看一个几乎人人都会踩的坑。

上面这个函数，第二个参数的默认值写成了一个空列表。调用第一次返回一，调用第二次返回一和二 —— 而你期望的是只有二。

原因是：默认值只在**函数定义的时候**创建一次，此后每次调用共用同一个列表。

正确写法在下面：默认值写成 None，进函数以后判断，如果是 None 才新建一个列表。这是 Python 里的标准写法，请当成模板记住。

结论一句话：默认参数不要用可变对象。

## P5｜可变与不可变

这一页把类型分成两栏。

不可变的有：整数、浮点数、字符串、元组、布尔值、不可变集合。

可变的有：列表、字典、集合，以及你自己定义的对象。

这条界线决定三件事：能不能当字典的键（只有不可变的能）、赋值以后改一个会不会影响另一个、以及上一页那个默认参数的坑。

## P6｜浅拷贝与深拷贝

三种写法，三种结果。

直接赋值是**别名**，两个名字指向同一个对象。

用切片是**浅拷贝**：外层是新列表，但里面的元素还是原来那些对象。

用 copy 模块的 deepcopy 是**深拷贝**，彻底独立。

看下面这个例子：改了原列表里第一行的第一个元素，别名跟着变、浅拷贝也跟着变，只有深拷贝没变。

做题时记住一条实用规则：一维列表复制用切片就够；**二维列表必须用列表推导式，对每一行各做一次切片**。用切片直接拷二维，坑和上一周那个别名陷阱是同一个。

## P7｜OJ 上最常用的异常处理

OJ 上很多题不告诉你有多少行输入，要求你读到文件结束为止。这一页给两种标准写法。

第一种，直接对 sys 的标准输入做 for 循环，读到文件尾自然结束。每行记得 strip，空行跳过。

第二种，写一个无限循环，把读入放在 try 里，捕获 EOFError 就 break。

两种都对，第一种更快，第二种更直观。

## P9｜容器选型

先看四种容器的性质。

列表：有序、可变、允许重复，用来做序列、栈、动态数组。

元组：有序、**不可变**、允许重复，用来做不变的记录，而且因为不可变，可以当字典的键。

集合：无序、可变、**不允许重复**，用来去重和判断存在。

字典：按插入顺序、可变、键不重复，用来做映射和计数。

选容器不是风格问题，是性能问题 —— 看下一页。

## P10｜操作复杂度：必须背下来

这张表请背下来。左边是列表，右边是集合和字典。

## P11｜实测：列表的 in 与集合的 in

二十万个元素，分别放进一个列表和一个集合，各做两百次成员判断。

## P12｜需要队列时用 deque，计数用 Counter

collections 模块里有三个东西，这学期会一直用。

deque，双端队列。两头进出都是常数时间。它就是 pop 零 的正确替代品，第七周讲队列、第十二周讲广度优先搜索时，全靠它。

Counter，计数器。传进一个序列，一遍扫完就得到每个元素的出现次数，还能直接取出现最多的前几个。

defaultdict，带默认值的字典。分组的时候不用再判断键在不在。

底下这句提醒很重要：Counter 一遍就是线性；而对集合里每个值都去列表里 count 一次，是**平方**。同样的功能，量级不同。

## P14｜大 O 忽略常数与低阶项

大 O 记号的意思是：只看增长的量级，忽略常数系数和低阶项。

三 n 平方加一百 n 加五百，写成大 O 就是 n 的平方。因为当 n 足够大的时候，量级压倒一切 —— 那个一百 n 和五百，在 n 平方面前根本不值一提。

这也解释了为什么优化常数常常没用：如果量级不对，把常数改小一倍，n 大一点就全吃回去了。

## P15｜常见复杂度级别

这张表把常见的复杂度和它们在一百万数据量下的实际操作次数列在一起。

常数级，一次。对数级，二十次。线性，一百万次。线性对数，两千万次 —— 这四个都能过。

平方级，一万亿次，过不了。指数级和阶乘级，天文数字，更过不了。

请把最右边那一列和中间那一列连起来记：排序和分治是线性对数，双重循环是平方，枚举子集是指数，全排列是阶乘。

## P16｜隐藏的复杂度

有两种复杂度是藏起来的，最容易漏。

第一种，循环里对列表做 in 判断。你看到的是一重循环，实际是两重，整体是平方。

第二种，循环里用加号拼接字符串。字符串不可变，每拼一次都要复制一遍已有内容，整体也是平方。

第二种的正确写法在注释里：把每一段 append 进列表，最后用 join 一次拼起来，这是线性的。

看代码估复杂度的时候，请把内建操作的代价也算进去，不要只数循环层数。

## P17｜从数据范围倒推算法

这是考场上最实用的一招，请务必掌握。

n 不超过十，可以用阶乘或者指数级，也就是全排列、暴力搜索。

n 不超过二十，可以用二的 n 次方，枚举子集、状态压缩。

n 不超过一百，可以用 n 的三次方，比如弗洛伊德算法、区间动态规划。

n 不超过一千，可以用 n 的平方，二维动态规划、两重循环。

n 不超过十万，要用线性对数：排序、二分、堆、优先队列。

n 不超过一百万，要用线性：一遍扫描、双指针、前缀和。

n 到了一亿以上，只能用对数或者常数：数学公式、快速幂。

底下这行是这张表的依据：OJ 的机器大约每秒能做一千万到一亿次基本操作。

## P21｜按收益排序的三招

三招，按收益从高到低排。

第一招，快速输入输出。把 input 换成 sys 标准输入的 readline，在大量行输入时提速很明显 —— 但注意它**保留行尾的换行符**，要自己 strip。更快的是一次把全部输入读进来再 split。输出同理，攒成一个列表最后一次写出去。

第二招，减少重复计算。把 len 的结果、把频繁用到的方法查找，提到循环外面去。

第三招，用内建函数。sum、max、sorted 都是 C 实现的，比你自己写等价的 Python 循环快一个量级。map 也快于列表推导式。

最后那行警告再说一遍：复杂度不对的时候，不要优化常数。那是在给一辆方向错了的车加油。

## P22｜埃拉托色尼筛

求素数的标准做法，复杂度是 n 乘以 log log n，基本上就是线性。

思路是反过来做：不去判断每个数是不是素数，而是把每个素数的倍数都划掉，剩下的就是素数。

代码里有一处细节值得说：内层循环从 i 的平方开始，而不是从二倍的 i 开始。因为比 i 的平方小的那些倍数，一定有一个比 i 小的因子，早就被划掉了。同理外层的条件是 i 乘 i 小于等于上限。

这两处不改也对，但改了能省下相当多时间。

## P23｜T-primes：恰好三个约数

这道题是筛法的经典应用。

先想清楚性质：一个数恰好有三个约数，当且仅当它是**某个素数的平方**。因为约数只能是一、它自己、和那个平方根。

所以做法是：先筛出一百万以内的素数表 —— 一百万是十的十二次方的平方根，题目上界就在那里 —— 然后对每个数求平方根，判断它是不是完全平方数，以及平方根是不是素数。

关键在中间那两行 while。为什么求完平方根还要校正？因为**浮点开方在大整数上会差一**。这正是第三周那条「浮点不可靠」的直接后果。这两行是本题最常见的 WA 来源，请照抄这个写法：先往下退到平方不超过它，再往上进到不能再进。

## P25｜通用方法

五条，按该用的顺序排。

第一，读错误信息的**最后一行**。Python 的报错是倒着看的，最后一行告诉你错误类型和位置。

第二，构造最小复现输入。把出错的那组数据一直砍，砍到再砍就不出错为止 —— 剩下的往往就直接指出了问题。

第三，打印中间状态，但要打到**标准错误**上去，这样不会污染 OJ 的输出。

第四，用调试器单步。PyCharm 打个断点，比来回加打印语句快得多。

第五，对拍。自己再写一个一定正确但很慢的暴力解，随机生成数据，比较两者的输出。这是唯一能发现「样例过了但仍然错」的办法。

## P26｜常见错误与对策

OJ 的五种反馈，各自意味着什么。

WA 是答案错，常见原因是边界没处理、读题漏了条件、输出格式不对、或者精度问题。

TLE 是超时，常见原因是复杂度过高、把 in 用在列表上、用 pop 零 当队列。

MLE 是超内存，常见原因是开了过大的数组，或者递归太深。

RE 是运行错误，常见原因是下标越界、除零、递归爆栈。

PE 是格式错，多了或少了空格换行。

拿到反馈先对号入座，不要一上来就改算法。
