## P6｜默认参数是可变对象

接着看一个几乎人人都会踩的坑。

这个函数的第二个参数，默认值写成了一个空列表。调用第一次返回一，调用第二次返回一和二 —— 而你期望的是只有二。

原因是：def 语句只在定义时执行一次，这个空列表也只被创建一次。此后每次调用不传这个参数，用的都是同一个列表对象。

正确写法在下面：默认值写成 None 作为哨兵，进函数以后判断，如果是 None 才新建一个列表。这是 Python 里的标准写法，请当成模板记住。

结论一句话：默认参数不要用可变对象。

## P7｜可变与不可变

这一页把类型分成两栏。

不可变的有：整数、浮点数、字符串、元组、布尔值、不可变集合。可变的有：列表、字典、集合，以及你自己定义的对象。

函数参数传的是引用。看这个例子：函数里对列表 append 了九十九，调用方的列表也跟着变了；而对整数加一，只是在函数内部重新绑定了一个新对象，外面的十纹丝不动。

记忆口诀：可变对象传进函数，修改会被外面看见；不可变对象在函数内重新赋值，外面完全不受影响。

## P8｜浅拷贝与深拷贝

三种写法，三种结果。

直接赋值是别名，两个名字指向同一个对象。用切片是浅拷贝：外层是新列表，但里面的元素还是原来那些对象。用 copy 模块的 deepcopy 是深拷贝，彻底独立。

例子里改了原列表第一行的第一个元素，输出是九十九、九十九、一：别名跟着变，浅拷贝也跟着变，只有深拷贝没变。原因就是切片只新建了最外层，内层两个小列表仍然被共享。

做题时记住一条实用规则：动态规划里保存一维状态，用切片就够；二维数组必须用列表推导式，对每一行各做一次切片，否则所有行仍是同一批对象。

## P12｜选型表

先看四种容器的性质。

列表：有序、可变、允许重复，用来做序列、栈、动态数组。

元组：有序、不可变、允许重复，用来做不变的记录，而且因为不可变，可以当字典的键。

集合：无序、可变、不允许重复，用来去重和判断存在。

字典：按插入顺序、可变、键不重复，用来做映射和计数。

一句话选型：要下标、要顺序，用列表；固定不变、想当字典键，用元组；只关心有没有，用集合；要映射关系，用字典。

## P15｜需要队列时用 deque

需要队列的时候，用 collections 模块里的 deque，双端队列。

右边进、左边进、左边出、右边出，四种操作都是常数时间。其中 popleft 就是列表 pop 零 的正确替代。

为什么列表的 pop 零 慢？列表底层是连续数组，弹出头部以后，所有元素都要整体前移一位，这是线性的。deque 底层是分块的双端结构，两端操作都是常数。

第十二周讲广度优先搜索时会用到它。如果拿列表的 pop 零 当队列，会把本该是点数加边数的线性算法，拖成点数平方。

## P17｜Counter 为什么快

接着说两个要点。

第一，Counter 一遍扫描，线性时间完成统计；而对集合里每个不同的值，都去列表里 count 一次，每次都要重新扫一遍列表，整体是平方。数据量一大，差距立刻显现。

## P19｜大 O 记号

大 O 描述的是：输入规模增长时，运行时间怎样增长。它忽略常数因子和低阶项。

三 n 平方加一百 n 加五百，写成大 O 就是 O n 平方，最高阶项决定量级。一百 n 写成 O n，即使常数很大也一样。

为什么忽略常数？因为 n 足够大时，量级压倒一切。n 等于一百万时，线性算法是一百万步，平方算法是一万亿步，快了一百万倍，常数是一百还是一根本无关紧要。

这也解释了为什么优化常数常常没用：量级不对，把常数改小一倍，n 大一点就全吃回去了。

## P20｜常见复杂度级别

这张表把常见复杂度和它们在一百万数据量下的操作次数列在一起。

常数级，一次，比如下标访问、哈希查找。对数级，二十次，比如二分查找。线性，一百万次，一遍扫描。线性对数，两千万次，排序和分治。这四个都能过。

平方级，一万亿次，过不了，典型是双重循环。指数级和阶乘级，天文数字，更过不了，分别对应枚举子集和全排列。

## P22｜怎么数（1/2）：单层与两重循环

那么拿到一段代码，怎么数它的复杂度？

只取首尾两个元素，是常数。一层循环把每个元素加起来，是线性。两重循环、内层次数和 n 同阶，是平方。

## P25｜从数据范围倒推算法

这是考场上最实用的一招，请务必掌握。依据是：OJ 的机器大约每秒能执行一千万到一亿次基本操作。

n 不超过十，可以用阶乘或者指数级，也就是全排列、暴力搜索。n 不超过二十，可以用二的 n 次方，枚举子集、状态压缩。n 不超过一百，可以用 n 的三次方，比如弗洛伊德算法、区间动态规划。n 不超过一千，可以用 n 的平方，二维动态规划、两重循环。

## P28｜快速输入输出

常数优化的第一顺位，是快速输入输出。

把 input 换成 sys 标准输入的 readline，大量行输入时提速明显。更快的是一次把全部输入读进来，再 split。输出同理，攒成一个列表，最后用 join 拼好一次写出去。

为什么有效？print 每次调用都有系统调用的开销，循环几万次 print 本身就可能超时。批量读、批量写几乎是零成本的改动。

小心一个坑：readline 会保留行尾的换行符，拿来做字符串比较时，记得先 strip。

## P29｜少做重复计算

第二招，少做重复计算。

上面慢的写法，在两重循环的条件里反复调用 len。下面快的写法，把 len 提到循环外算一次，再把 res 点 append 这个方法绑成局部变量。

为什么有效？len、点 append 这类查找每次都要重新解析一次，提到循环外只算一次，在千万级的循环里能省下明显的时间。但请注意，这改变不了复杂度，只是降低常数。

## P30｜用内建函数

## P31｜埃拉托色尼筛

接下来看一个例子：埃拉托色尼筛。

判断一个数是不是素数，朴素做法是试除到根号 n，一次查询没问题；但要判很多个数时，就该预处理。

思路是反过来做：不去逐个判断，而是把每个素数的倍数都划掉，剩下的就是素数。先开一个全为真的布尔数组，把零和一标成假；外层 i 从二开始，只要 i 乘 i 不超过上限；如果 i 是素数，就从 i 的平方开始，每隔 i 划掉一个。复杂度是 n 乘 log log n，基本是线性。

内层从 i 的平方开始，是因为更小的倍数一定有比 i 小的因子，早就被划掉了。最后输出一百以内的二十五个素数。

## P32｜经典应用：T-primes（恰好 3 个约数的数）

这道题是筛法的经典应用。

先想清楚性质：一个数恰好有三个约数，当且仅当它是某个素数的平方。因为约数只能是一、它自己、和那个平方根。

所以做法是：先筛出一百万以内的素数表，一百万是十的十二次方的平方根，题目上界就在那里。然后对每个数求平方根，判断它是不是完全平方数，以及平方根是不是素数。

例子里一、四、九、十二、十六、二十五、三十六、四十九，符合条件的是四、九、二十五、四十九。

## P33｜两行 while 校正在纠正什么

上一页代码中间那两行 while，是本题最常见的 WA 来源。

为什么求完平方根还要校正？因为 x 的零点五次方是用双精度浮点算的，尾数只有五十二位，对大整数开方可能差一。这正是第三周「浮点数不可靠」的直接后果。

怎么修：算出近似根 r 以后，用纯整数运算拿 r 乘 r 和 x 比较。先往下退，退到平方不超过 x；再往上进，进到下一个的平方超过 x 为止。这样得到的 r 一定准确，彻底绕开浮点误差。请照抄这个写法。

## P34｜E03143 验证“歌德巴赫猜想”

再看一道例题，E 零三一四三，验证歌德巴赫猜想。

猜想内容是：任一大于二的偶数，都能写成两个素数之和。

做法是先用埃氏筛预处理一万以内的素数表，然后从二开始，从小到大枚举 a，直到 n 的一半。只要 a 是素数，n 减 a 也是素数，就输出这一组。第一次找到的就是 a 最小的一组。

## P36｜通用方法

五条，按该用的顺序排。

第一，读错误信息的最后一行。它告诉你错误类型和位置。

第二，构造最小复现输入。把出错的那组数据一直砍，砍到再砍就不出错为止，剩下的往往就直接指出了问题。

第三，打印中间状态，但要打到标准错误上去，这样不会污染 OJ 的输出。

第四，用调试器单步。PyCharm 打个断点，比来回加打印语句快得多。

第五，对拍。自己再写一个一定正确但很慢的暴力解，随机生成数据，比较两者输出。第十六周复习时会用到。

## P37｜常见错误与对策

OJ 的六种反馈，各自意味着什么。

WA 是答案错，常见原因是边界没处理、读题漏了条件、输出格式不对，或者精度问题。

TLE 是超时，常见原因是复杂度过高、把 in 用在列表上、用 pop 零 当队列。

MLE 是超内存，常见原因是开了过大的数组，或者递归太深。

RE 是运行错误，常见原因是下标越界、除零、递归爆栈。

PE 是格式错，多了或少了空格换行。CE 是编译错，也就是语法错误。

拿到反馈先对号入座，不要一上来就改算法。

## P38｜三条考场纪律

三条纪律。

第一，样例过了不等于对。样例通常只覆盖最普通的情况，至少再手造一组边界数据，比如 n 等于一、全部相同、取最大值。

第二，超时先看复杂度，不要急着调常数。数量级不对，怎么优化常数都没用。

第三，一道题卡住十五分钟就换题。回来时往往一眼就能看出问题。

## P41｜本周小结

小结五条。

第一，默认参数别用可变对象；二维结构拷贝要对每一行各切一次。

第二，容器复杂度表要背：列表的 in 和 pop 零 是线性，集合和字典的 in 是常数，需要队列就用 deque。

第三，大 O 忽略常数与低阶项；先看数据范围，再定复杂度，最后想算法。

第四，常数优化的顺序是：快速输入输出、减少重复计算、用内建函数。复杂度不对时不要优化常数。

第五，浮点开方在大整数上会差一，边界要用整数校正。
