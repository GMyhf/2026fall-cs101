## P11｜图灵机：纸带加读写头加状态机

图灵机是图灵在一九三六年提出的，比第一台电子计算机还早十年。它的组成只有三样东西。

一条无限长的纸带，每格写一个符号。一个读写头，可以读、可以写、可以左移或右移一格。一个状态机，有有限个状态和一张规则表。

规则的形式是：根据当前状态和读到的符号，决定写入什么符号、往哪边移动、进入哪个下一状态。每一步只做三件事：写一格、挪一步、换一个状态。整个计算的概念，就被压缩成了一条纸带加一张规则表。

---

## P12｜二进制加一的图灵机：只要三条规则

来看一台具体的图灵机，做二进制加一。读写头从最低位，也就是最右边出发，只用一个状态 q 零。

规则只有三条。读到一，就写零，左移，状态不变，意思是一加一得一零，本位写零、进位向左。读到零，就写一，不动，停机，意思是吸收了进位，收工。读到空白，也写一，停机，意思是走到最左边了，补一位一。

移动方向里，L 是左移，R 是右移，N 是不动；下划线表示空白格。

这和你在纸上手算一模一样：从最右边开始，遇一写零进位，遇零写一收工。图灵机只是把这个过程写成了规则表。

---

## P13｜手动跑一遍：一零一一加一

我们手动跑一遍，纸带上是一零一一，读写头在最低位。

第一步，读到一，写零，左移，这是进位。第二步，又读到一，写零，再左移。第三步，读到零，写一，停机。

纸带上变成一一零零，也就是十一加一等于十二，一共三步。

你可以自己再试一一一：连续三次进位之后读到空白，补一个一，得到一零零零，一共四步。

## P14｜它划定了「可计算」的边界

图灵机重要在两件事上。

第一件叫丘奇 图灵论题：任何直觉上可计算的函数，都能被图灵机计算。你的 Python 程序、C 加加 程序，能算的东西不比图灵机多，只是快得多、好写得多。所有通用编程语言在「能算什么」上是等价的，差别在效率和表达。

第二件是停机问题不可判定：不存在一个程序，能对任意程序加任意输入，判断它会不会停机。

请注意这句话的分量。它不是说「我们还没想到办法」，而是证明了不可能。这是计算的根本边界，不是工程难度问题。

---

## P15｜为什么不可能？一个反证

为什么不可能？我们用反证法走一遍思路。

假设有人写出了一个万能的判定函数 halts，传入程序 p 和输入 x，p 会停机就返回真，否则返回假。

然后我们构造一个捣乱的函数 trouble，它接收一个程序 p，先问 halts：p 拿自己当输入会停机吗？如果会，它就偏偏进入死循环；如果不会，它就立刻返回。

现在问：trouble 拿自己当输入，停不停机？如果 halts 说停，它就进入死循环，不停，矛盾。如果 halts 说不停，它就立刻返回，停了，又矛盾。

两头都矛盾，只能是假设错了，这样的 halts 根本写不出来。这就是图灵一九三六年的对角线论证。

## P18｜第 3 部分　冯·诺依曼结构

第三部分，冯 诺依曼结构。从数学模型回到真实的机器，核心一句话：程序本身也是数据。

## P19｜五大部件

冯 诺依曼结构有五大部件：存储器、运算器、控制器、输入设备、输出设备。运算器负责算术与逻辑运算，控制器负责取指、译码和指挥，两者合起来就是我们今天说的 CPU。

但这张图真正的重点不是部件的个数，而是存储器那一格：程序和数据放在一起。

这就是核心思想，叫存储程序。程序本身也是数据，所以同一台机器能跑不同的程序，不需要重新接线；装一个新软件，就是往存储器里写一段新数据。

---

## P20｜在 Python 里亲眼看到「程序也是数据」

在 Python 里，我们可以亲眼看到这件事。

定义一个函数 f，取它编译后的字节码，类型是 bytes，就是一串字节。函数还可以像数据一样赋值给另一个变量、作为参数传给 map。再进一步，一个字符串交给 exec，也能被当作程序执行，打印出四十二。

对应关系是：字节码就是存储器里的一串字节，解释器读这串字节来执行，指令就是数据。

也提醒一句：「数据能被当作程序执行」也是很多安全漏洞的根源。不要用 exec 或 eval 去执行来路不明的字符串。

## P21｜指令周期：取指、译码、执行、写回

CPU 干活是一个循环，分四步。

取指，按程序计数器 PC 从存储器取一条指令。译码，看清是什么操作、操作数在哪。执行，由运算器做运算，或者访问存储器。写回，把结果写回寄存器或存储器。然后 PC 指向下一条指令，循环往复，每秒几十亿次。

和图灵机对照一下：图灵机是读一格、查规则、写移换状态；CPU 是取一条指令、译码、执行写回、PC 前进。两者都是一步一步查表执行的循环，只是 CPU 的「纸带」可以随机访问。

---

## P22｜冯·诺依曼瓶颈与缓存

这个结构有一个与生俱来的问题，叫冯 诺依曼瓶颈：CPU 和内存之间共用一条总线，取指令和取数据要排队。CPU 越来越快，内存跟不上，CPU 大部分时间在等数据。

现代 CPU 的对策是多级缓存：在 CPU 旁边放小而快的 L 一、L 二、L 三缓存。从内存取数时，连同附近的一整块，也就是一个缓存行，常见是六十四字节，一起搬进缓存。下一次访问如果恰好在这一块里，就不用再等内存。

这就是「访问连续内存比跳着访问快」的根源。第六周讲矩阵时我们会看到：按行遍历二维数组，比按列遍历快。

## P23｜存储层次

这张表把整个存储层次列全了，请注意最右边那一列的相对代价。

寄存器几百字节，访问不到一纳秒，代价记作一。L 一缓存几十 KB，约一纳秒，代价约三。L 二和 L 三缓存几 MB 到几十 MB，约十纳秒，代价约十五。内存是几到几十 GB，约一百纳秒，代价约两百。固态硬盘几百 GB 到几 TB，约一百微秒，代价约十万。机械硬盘几 TB，约十毫秒，代价约一千万。

从上到下，容量越来越大、速度越来越慢、单价越来越低。粗略记两个数：一次内存访问约等于两百次寄存器访问，一次固态硬盘访问约等于一千次内存访问。

## P24｜换成人的时间尺度

这些数字太抽象，我们换成人的时间尺度：假如访问一次寄存器要一秒。

那么访问 L 一缓存是三秒，像从抽屉里拿东西。L 二、L 三是十五秒，像去书架上取一本书。内存约三分钟，像下楼取快递。固态硬盘约一天，像寄一封快递到外地。机械硬盘约四个月，像寄一封平信去南极。

这就是按上一页相对代价换算出来的：十的五次方秒约二十八小时，十的七次方秒约一百一十六天。图上条形的长度只示意顺序，不按比例。

## P26｜四种常用进制

先看四种常用进制。

二进制，Python 前缀是零 b，数字只有零和一，是机器本身用的。八进制，前缀零 o，常见于 Unix 的文件权限，比如七五五。十进制，没有前缀，是给人用的。十六进制，前缀零 x，数字是零到九加 A 到 F，用在内存地址、颜色、字节转储里。二百三十三这个数，在四种进制下的写法都列在表的最后一列。

为什么程序员爱用十六进制？因为一位十六进制正好对应四位二进制，一个字节就是两位十六进制。一一一零一零零一，一眼读成 e 九，比数八个零一省事得多。

---

## P27｜Python 里的进制转换

Python 里进制转换有现成的函数：bin、oct、hex 分别转成二进制、八进制、十六进制的字符串，注意它们带着零 b、零 o、零 x 的前缀。

反过来，int 函数的第二个参数是进制，可以把字符串按指定进制解析成整数，字符串可以不带前缀。

更常用的是 f 字符串里的格式说明符：冒号后面写 b、o、x，输出不带前缀的结果；写零八 b，就是补足八位的二进制。

两个常见的坑：要去掉零 b 前缀，得切片从下标二开始；负数的 bin 得到的是负号加原来的二进制，而不是补码。

## P28｜除基取余，余数逆序读

手工转换的办法也要会：除基取余，余数逆序读。

二百三十三不断除以二：商一百一十六余一，商五十八余零，商二十九余零，商十四余一，商七余零，商三余一，商一余一，商零余一。从下往上读，得到一一一零一零零一。

反过来按权展开验证：一百二十八加六十四加三十二加八加一，正好二百三十三。

为什么要逆序？因为第一次除得的余数是最低位，也就是二的零次方那一位，最后一次得到的是最高位。

---

## P29｜二进制与八进制、十六进制：分组就行

二进制转八进制、十六进制更简单，分组就行：从最低位开始，八进制三位一组，十六进制四位一组。

一一一零一零零一，四位一组，一一一零是 e，一零零一是九，得到零 x e 九。三位一组，从右往左分成零零一、一零一、一一，也就是一、五、三，倒过来读是三五一，得到零 o 三五一。

为什么可以直接分组？因为八是二的三次方，十六是二的四次方，每三位或四位二进制恰好组成一位，组与组之间互不进位。十进制的十不是二的幂，所以只能除基取余。

## P30｜例题：E 零二七三四　十进制到八进制

这道例题是本周练习第一题，十进制到八进制，题号 E 零二七三四：输入一个非负整数，输出它的八进制表示。

最短的写法是用 oct 转完，切掉前两个字符的前缀。但要注意边界：输入是零时要单独输出零。

也要会不用内置函数的写法，就是手写除基取余：循环里把 n 模八的余数存起来，再把 n 整除八，直到 n 变成零，最后把余数反过来拼接。这里同样有零的边界：n 等于零时循环一次都不执行，所以末尾要补一个「或者零」。反转是因为余数是从低位到高位得到的。

## P31｜原码、反码、补码：以八位表示负五

负数在计算机里怎么存？历史上有三种方案，这张表以八位的正五和负五为例放在一起比。

原码，最高位当符号位，负五就是一后面跟零零零零一零一。问题是它有正零和负零两个零，而且做加减法要先判断符号。

反码，负数是原码除符号位外按位取反，负五是一一一一一零一零。问题是仍然有两个零。

补码，负数是取反之后再加一，负五是一一一一一零一一。零是唯一的，而且减法就是加一个负数，硬件只需要一套加法器。

所以现代计算机统一用补码。求法记住一句：正数不变；负数按位取反，再加一。

## P32｜用 Python 看补码；n 位补码的范围

用 Python 看补码，关键是这一个表达式：x 按位与上「一左移 bits 位再减一」。一左移八位减一，就是零 x FF，八个一；和它按位与，就是只保留低八位，正好是八位机器里存的那串位。

所以五的补码是零零零零零一零一，负五是一一一一一零一一，负一是八个一。负五按位与零 x FF 得到二五一，这是把同一串位当成无符号数来读，开头那个现象就解释了。

n 位补码的范围，是负的二的 n 减一次方，到二的 n 减一次方减一。负数那一头多一个：一后面七个零是负一百二十八，没有对应的正一百二十八。八位是负一百二十八到一百二十七；三十二位，也就是 C 加加 的 int，大约正负二十一亿；六十四位的 long long，大约正负九点二乘十的十八次方。

## P33｜为什么补码让减法变成加法：算五减七

来算一个五减七，看补码怎么把减法变成加法。

五减七等于五加负七。先求负七的补码：七是零零零零零一一一，取反是一一一一一零零零，加一得一一一一一零零一。

把它和五的补码零零零零零一零一按位相加，得到一一一一一一一零。

这是几？最高位是一，所以是负数。再求一次补码看绝对值：取反得零零零零零零零一，加一得二。所以结果是负二，正确。

要点是：加法器根本不知道哪个是负数，它只管按位相加；如果最高位还有进位，直接丢掉，只保留八位。同一套电路，加减法全包了。验证七减五，留作思考题。

## P34｜溢出：C 加加 里最常见的 WA 来源

补码的范围有限，就会溢出。八位里一百二十七加一，零一一一一一一一加一，得到一后面七个零，变成了负一百二十八，正数加正数却得到了负数。

代码里借 ctypes 用 C 的三十二位 int 来演示：二一四七四八三六四七加一，变成了负二一四七四八三六四八。而 Python 自己算同一个式子，得到正确的结果；二的一百次方也能完整打印出来。

这就是 Python 与 C 加加 的区别：Python 的 int 是任意精度的，不会溢出，本课用 Python，这个坑天然避开了。但 C 加加 的 int 是三十二位，用它做题时这是最常见的 WA 来源。对策是估计中间结果的量级，超过大约二乘十的九次方，就用 long long。

## P35｜六个位运算符

Python 有六个位运算符，都是按二进制逐位操作。

与，六按位与三得二。或，六按位或三得七。异或，相同为零、不同为一，六异或三得五。取反，按位取反六得负七。左移，一左移十位得一千零二十四，左移 k 位就是乘二的 k 次方。右移，一千零二十四右移三位得一百二十八，右移 k 位就是整除二的 k 次方。

为什么取反六是负七？取反把所有位都翻过来。而补码里「取反再加一」等于取相反数，所以「只取反」就是相反数再减一：取反 x 等于负 x 减一。

## P36｜三个常用技巧

三个技巧，考试和刷题都会用到。

第一个，判奇偶：n 按位与一，结果是零就是偶数，是一就是奇数，和 n 模二等价。

第二个，n 按位与 n 减一，效果是把最低位的那个一清零。十二按位与十一得八。由它立刻得到一个推论：二的幂在二进制里只有一个一，清掉就剩零，所以正数 n 按位与 n 减一等于零，当且仅当 n 是二的幂。顺带一提，统计一的个数叫 popcount，可以用 bin 转成字符串再 count。

第三个，异或的两个性质：一个数和自己异或得零，和零异或得它自己。合起来就能解力扣一三六题，只出现一次的数字：一串数里只有一个出现一次，其余都出现两次，全部异或起来，成对的互相抵消，剩下的就是答案。

## P37｜按位看：n 与 n 减一，异或累积

这一页把上一页的两个技巧按位展开。

左边，n 等于十二，二进制一一零零；n 减一等于十一，一零一一。n 减一的效果是，把最低位的一变成零，它右边的零全变成一。两者按位与，这几位全部清零，高位不变，得到一零零零，也就是八。

右边，是异或累积的过程表。数组是四、一、二、一、二，r 从零开始依次异或：四，五，七，六，最后回到四。两个一、两个二各自抵消，剩下四。

而且结果与顺序无关，因为异或满足交换律和结合律。

## P38｜IEEE 七五四双精度

浮点数是怎么存的？双精度一共六十四位，分成三段：一位符号位，十一位指数，五十二位尾数。

值等于负一的 S 次方，乘以一点尾数，再乘以二的「指数减一零二三」次方。

这其实就是二进制的科学计数法。十进制写六点零二乘十的二十三次方，二进制写一点几乘二的 e 次方。尾数决定精度，大约十五到十七位十进制有效数字；指数决定范围，大约十的正负三百零八次方。

关键结论是：尾数是二进制小数，只能精确表示 k 除以二的 n 次方这种数。十进制的零点一，无法精确表示。

## P39｜为什么零点一无法精确表示？

为什么零点一无法精确表示？类比一下十进制。

十进制里的三分之一，是零点三三三无限循环，因为三不是十的因子，截断就有误差。二进制里的十分之一也一样：十等于二乘五，五不是二的因子，所以写成二进制是零点零零零一一零零一一，零零一一无限循环，只能截断到五十二位。

代码里有三种方式看它的真面目。打印到小数点后二十位，能看见末尾多出来的五五五。用 hex 方法看，尾数是一串九后面跟一个 a，这就是循环被截断后又进了一位。用 Decimal 包一个浮点零点一，能看到存进去的真实值，是一长串数字。

## P40｜浮点数陷阱与正确的比较方式

上一页的结论，到这一页就变成了具体的坑：零点一加零点二打印出来是零点三后面跟一串零再跟一个四，所以它和零点三比较，结果是 False。

正确的比较方式有三种。用 math 模块的 isclose，做相对误差比较。或者自己判断两数之差的绝对值小于一个很小的阈值，比如十的负九次方，这是绝对误差。如果需要十进制的精确运算，比如算钱，就用 decimal 模块的 Decimal，从字符串零点一构造，零点一加零点二就精确等于零点三。

注意一定要从字符串构造。如果直接把浮点数零点一传给 Decimal，就会把误差一起带进来，也就是上一页看到的那一长串。

## P41｜另一个陷阱：大整数放进浮点会丢精度

另一个陷阱：大整数放进浮点数会丢精度。

二的五十三次方加一，转成浮点数之后，和二的五十三次方「相等」了。十的十八次方加一，用单斜杠除以一再转回整数，末位的一丢了；用双斜杠整除，就保持整数，结果正确。再比如一个大奇数除以二，用单斜杠的结果和双斜杠的结果居然相等，判断错了；判断整除，应该用取模是否等于零。

为什么界限是二的五十三次方？尾数五十二位，加上隐含的一位，是五十三位有效二进制数字。超过它的整数，相邻浮点数之间开始有空隙。

所以做题时：判断整除用取模；整数运算全程用整除和取模，不要经过单斜杠；开方取整用 math 点 isqrt，不要用 n 的零点五次方再取整。

## P44｜ASCII：七位，一百二十八个字符

ASCII 用七位表示一百二十八个字符。整张表不需要背，但有几个数字要记住。

字符零是四十八，是数字的起点，零到九连续。大写 A 是六十五，大写字母连续。小写 a 是九十七，小写字母连续。空格是三十二，正好是一左移五位。

再看图：大写 A 和小写 a 的二进制只差一位，就是值为三十二的那一位，零是大写，一是小写。

所以记住三个数就够了：四十八、六十五、九十七。其余靠「连续」推出来，比如大写 Z 是六十五加二十五，等于九十。

## P45｜ord 与 chr：字符与编号互转

ord 把字符转成编号，chr 把编号转回字符。

有了它们，几件事就顺理成章。小写字母的编号减三十二，得到大写。更巧的是位运算版：按位或三十二是置位，转小写；按位与上取反三十二是清位，转大写；异或三十二是翻转，大小写互换，因为那一位就是大小写的开关。数字字符减去字符零，得到它代表的数值；字母减去小写 a，得到它在字母表里的序号。

做题时，内置方法更清楚：upper、lower、swapcase、isdigit、isalpha。而 ord 减 ord 小写 a 这个写法，常用来把字母映射到零到二十五，当计数数组的下标。

## P46｜字符集不等于编码方式

ASCII 只够英文。全世界的字符要靠 Unicode，但请先分清两个词。

Unicode 是字符集，它给世界上每个字符一个码点，也就是编号。「中」的码点是 U 加四 E 二 D，ord 「中」就等于十六进制的四 e 二 d。

UTF-8 是编码方式，它规定码点怎么变成字节序列，而且是变长的。表里列了四档：码点在七 F 以内用一个字节，就是 ASCII，比如大写 A；再往上用两个字节，比如带重音的 e；到 FFFF 以内用三个字节，汉字通常在这一档；更大的码点用四个字节，比如表情符号。每一档都有固定的字节模板。

## P47｜手工编码一次：「中」

我们手工编码一次「中」。

码点四 E 二 D 落在三字节那一档，所以用三字节模板：第一个字节是一一一零加四个空位，后两个字节都是一零加六个空位。把码点的十六位二进制，按四位、六位、六位依次填进去。

第一个字节填进零一零零，得到 E 四；第二个字节填进一一一零零零，得到 B 八；第三个字节填进一零一一零一，得到 A D。图里灰色是模板固定的前缀，彩色是码点的位。

## P48｜str 与 bytes：字符数不等于字节数

在 Python 里，文本和字节是两种类型。

字符串「中 A」的长度是二，因为 str 是字符序列，len 数的是字符。把它按 UTF-8 编码成 bytes，长度是四，因为汉字占三个字节，字母占一个。再 decode 回来，又得到「中 A」。

两种类型，两种单位。str 是字符序列；bytes 是字节序列，文件和网络里实际传的是它。encode 把 str 变成 bytes，decode 反过来，两边必须用同一种编码。

## P49｜乱码的本质

乱码的本质，就是用 A 编码存的字节，拿 B 编码去解。

「你好」用 UTF-8 编码是六个字节。拿 GBK 去解，GBK 每两个字节当一个字，就解出了「浣犲ソ」这样的乱码。用 UTF-8 解，又恢复成「你好」。字节本身没有坏，坏的是解读方式。

所以读写文件时，请显式指定编码，在 open 里写上 encoding 等于 utf-8。为什么要显式写？不写的话 Python 用系统默认编码，中文 Windows 上常是 GBK，Linux 和 macOS 上是 UTF-8，同一份代码换台机器就乱码。
