## P2｜什么是递归

先看最短的例子：阶乘。

n 小于等于一的时候返回一，这一支叫**基例**。否则返回 n 乘以「n 减一的阶乘」，这一支是递归调用，而且参数在往基例靠近。

递归的定义就是这么一句话：函数在自己的定义里调用自己。

难的不是写出这五行，而是相信它 —— 下面几页就讲这件事。

---

## P3｜递归三法则

三条法则，缺一不可。

必须有基例。必须改变状态并向基例逼近。必须调用自身。

三条里缺任何一条，写出来的就是死循环 —— 或者更准确地说，是一路压栈直到崩溃。

写完一个递归函数，请对着这三条各检查一遍，这个习惯能省掉一大半的调试时间。

---

## P4｜递归的思维方式：相信它

这一页讲的是心法。

写递归的时候**不要在脑子里展开每一层**。你展不开的，三层以后就乱了。

你只需要回答两个问题：最小的情况怎么办 —— 这是基例；以及，假设「更小的问题已经被解决了」，怎么用它拼出当前问题的答案。

第二个问题是关键。你不需要知道它**怎么**解决的，只需要假设它**已经**解决了。这一步的心理障碍，是学递归最大的门槛。

## P5｜例：求数组之和

用刚才那两个问题来做一道题：求数组的和。

最小情况：空数组，和是零。

假设「剩下部分的和」已经算好了，那么整体的和就是首元素加上它。两行写完。

但请看下面那个警告：**每一层都做切片是不行的**。切片本身是线性的，套在 n 层递归里就变成了平方。

实战写法在第二个函数里：用一个下标参数代替切片。同样的思路，复杂度从平方回到线性。这类「思路对但写法拖垮复杂度」的问题，在递归里特别常见。

## P6｜递归与迭代可以互相改写

任何递归都能改写成迭代，反过来也一样。

这一页用进制转换做例子：上面是递归版，贴近数学定义，三行；下面是迭代版，用一个**显式的栈**。

两者的取舍：递归代码短、更接近问题的数学描述；迭代没有深度限制、常数更小。

一条实用建议在底下：能写成简单循环的，就别用递归。递归是用来处理「问题的结构本身就是递归的」那类题，不是用来炫技的。

## P8｜系统调用栈

看这张图，三的阶乘的调用过程。

调用三的阶乘时，压入一个栈帧；它调用二的阶乘，再压一个；再调用一的阶乘，又压一个。到了基例开始返回，栈帧一个个弹出，每一层拿到下层的返回值再算自己的。

每个栈帧里放着这一层的参数、局部变量和返回地址。

所以一句话：**递归就是在用系统栈**。而栈空间是有限的，递归太深就会溢出。下面三页讲这件事在今天的 Python 上究竟是什么样。

---

## P9｜递归深度限制：其实有两道墙

很多人以为递归深度只有一道限制，其实有两道。

墙一，是解释器自己数的嵌套层数。撞上去抛 RecursionError，**看得懂**，而且 setrecursionlimit 管得到。

墙二，是**C 调用栈**，主线程通常八兆。撞上去是段错误，进程直接死，没有任何可读的信息；setrecursionlimit **管不到**。

理解它们的关系：墙一本来是设在墙二前面的护栏。所以把 setrecursionlimit 调大，等于把护栏往前挪，而墙二一动没动 —— 于是原本「能看懂的异常」就变成了「没有 traceback 的运行错误」。

调大递归限制不是免费的，它换来的可能是更难诊断的崩溃。

---

## P10｜3.11 之后两道墙的位置变了

这一页是本机实测的结果，请先看清楚上下文：CPython 三点十二、Linux，已经把递归限制调到很大。

第一行，**纯 Python 递归，三十万层照跑**，连三十二 KB 的线程栈都够用。

第二行，递归**穿过 C 代码**，比如用了 lru_cache 装饰器，**三千三百三十一层就封顶**，抛 RecursionError；而且把线程栈加到六十四兆**也没用**，还是这个数。

原因是三点十一起，Python 到 Python 的调用在解释器主循环内部展开，不再占用 C 栈；而三点十二又给 C 层的递归单设了一道 setrecursionlimit 管不到的上限。

请把这两行当成**某个环境下的实测值，不是语言规范**。这恰恰是不该依赖它的理由 —— 评测机是什么版本，你并不知道。

## P11｜什么叫「递归穿过 C 代码」

上一页那个词需要解释：调用链中间夹了一层 C 实现的东西，就会掉进墙二。

最常见的一种，本周就在教：**用 lru_cache 或者 cache 做的记忆化搜索**。

其他还有：打印或者取一个深度嵌套列表的字符串表示；在 sorted 的 key 里调用递归函数；正则的回溯匹配；深拷贝；序列化成 JSON 或者 pickle。

至于 threading 的 stack_size，它加大的是**新线程的 C 栈**，也就是把墙二往后推。三点十以前确实有效；三点十一以后对纯递归没必要；对穿过 C 的递归**没用**。

最后一句请记住：**别把它当护身符**。它能不能救你，取决于评测机的版本和你的递归形状，这两件事你都控制不了。

## P12｜唯一与版本、评测机都无关的做法：显式栈

那么深递归的题到底该怎么写？答案在这一页：显式栈。

上面是递归版，下面是同一件事的显式栈版本 —— 自己拿一个列表当栈，手动压入弹出。它的深度只受内存限制。

两个结果对照：小深度上两者一致；而一百万层，只有显式栈那一版能跑出来。

底下那句话是本节的结论：**深递归题的可靠解法只有一个，就是显式栈**。另外两招 —— 调大限制、加大线程栈 —— 都是看运气的补丁，而且它们失败的方式恰恰是最难诊断的那种。

## P13｜进程的虚拟地址空间

顺便把整张内存图看一眼，第十三周还会回来。

从高地址往低地址：内核区；**栈**，放函数调用帧，向下增长，通常八兆 —— 就是刚才那道墙二；中间一大片空白；**堆**，放动态分配的对象，向上增长；再往下是全局和静态数据；最下面是代码段。

「虚拟」这个词的意思是：每个进程都以为自己独占整个地址空间，实际由操作系统加上内存管理单元映射到物理内存。这也是为什么两个程序可以同时用同一个地址而互不干扰。

## P15｜序曲：朴素斐波那契是指数级

先看一个反面例子。

直接按定义写斐波那契，画出调用树就明白问题在哪：算五的时候要算四和三，算四的时候又要算三和二 —— **三被算了两次，二被算了三次**。

层数越深，重复越多，整体是指数级。

这个现象有个名字，叫**重叠子问题**。它是第十周动态规划两个前提之一，现在先记住这个词。

---

## P16｜三种修法

同一个问题，三种修法，都是线性。

修法一，记忆化：在函数上加一个 lru_cache 装饰器，算过的结果自动存下来。**一行代码把指数降成线性**，这大概是本课性价比最高的一行。

修法二，迭代递推：两个变量滚动往前推，线性时间、常数空间。

修法三，自底向上填表：开一个数组，从小到大填。这就是动态规划的标准形状，第十周会正面讲。

三者结果一致。请注意修法一的副作用 —— 它正是上一节说的「穿过 C 代码」，深度大的时候会撞墙二。

## P17｜第一部：汉诺塔

第一部，汉诺塔。它的解法就是「相信更小的问题已经解决」的最好示范。

三步：把上面 n 减一个盘从 A 借助 C 移到 B；把最大的第 n 个盘从 A 移到 C；再把那 n 减一个盘从 B 借助 A 移到 C。

第一步和第三步你不需要知道具体怎么移 —— 假设它们已经解决了就行。

移动次数的递推是：T n 等于二倍的 T n 减一，再加一；T 一等于一。解出来是**二的 n 次方减一**。

---

## P18｜汉诺塔实现

代码就是那三步，一行一步，加上一个 n 等于零的基例。

三个盘子，七次移动，和二的三次方减一相符。下面那行列出了一到七个盘子的次数：一、三、七、十五、三十一、六十三、一百二十七。

最后这句话给你一个指数复杂度的实感：六十四层汉诺塔需要二的六十四次方减一次移动，大约一点八乘十的十九次方。每秒移动一次，需要五千八百五十亿年。

这就是为什么第四周那张表里，指数级后面画的是叉。

## P19｜第二部：全排列

第二部，全排列。它是**回溯模板的原型**，下一周整整一节都建立在这一页上。

结构是：如果路径长度等于 n，就收下一个答案；否则枚举每个还没用过的元素，标记为已用、加入路径、递归、然后**撤销**。

三个细节，请逐个记住。

第一，收答案时必须写 path 加切片，**拷贝一份**。否则收进去的是同一个列表的引用，最后全部答案会变成一样的。

第二，递归回来之后必须还原状态 —— 弹出路径、清掉标记。这个动作就叫**回溯**。

第三，复杂度是 n 的阶乘乘以 n，所以这类题的 n 通常不超过十。这一条对得上第四周那张倒推表的第一行。

## P21｜分治：分、治、合

分治的三步是：把问题分成若干个同类的小问题、递归解决、再把结果合起来。

四个例子横向对比。

归并排序：对半切，合并两个有序表，线性对数。

快速排序：按枢轴划分，**不需要合并**，平均线性对数。

二分查找：只保留半边，不需要合并，对数。

快速幂：指数减半，合的时候相乘，对数。

注意第二列和第三列的关系：合并那一步的代价，直接决定了总复杂度。

---

## P22｜快速幂与二分查找

两段代码都要会默写。

快速幂：把指数折半，算出一半的结果之后自乘；指数是奇数就再乘一个底数。支持取模。Python 的内建 pow 传第三个参数就是快速幂，考试直接用它。

二分查找这一版请**只记这一版**：求第一个大于等于目标的位置。区间取左闭右开，中点偏小，小于目标就把左边界推到中点加一，否则把右边界收到中点。这样写不会死循环，也不会漏边界。

底下这行是它的两个变体：求「最后一个小于等于目标的位置」，就用这一版对目标加一的结果再减一。不要另写一份，改写比重写安全。

## P23｜最大公约数

辗转相除，两行。

原理在底下那句：a 和 b 的公约数集合，与 b 和「a 除以 b 的余数」的公约数集合**完全相同**。所以问题可以一直缩小，直到余数为零。

顺带给出最小公倍数：两数之积除以最大公约数。注意代码里是**先除后乘**，避免中间结果过大 —— 在 Python 里这不算问题，但在 C 加加 里会溢出，这是个好习惯。

## P25｜打印调用树

第一个办法：给递归函数加一个深度参数，打印的时候按深度缩进。

这样打出来的就是一棵**调用树**，缩进就是栈深度。

看这个例子：算四的斐波那契，打出来能清楚看到二被算了两次。**看到重复的子树，就该上记忆化** —— 这个判断可以直接从打印结果里读出来，不用推理。

另外推荐 pythontutor 点 com，它能逐步展示栈帧的压入和弹出。理解递归，这个工具比任何讲解都直观。

## P26｜递归的常见错误

五种症状，各对一个原因。

RecursionError：没有基例，或者没有向基例逼近。

结果全都一样：收集答案时忘了拷贝。

结果多了或少了：忘了回溯，也就是没有还原状态。

超时：有重叠子问题却没有记忆化。

运行错误而且没有 traceback：递归太深撞穿了 C 栈，也就是墙二。在新版 CPython 上，更常见的表现是 RecursionError。

拿到反馈先对号入座，这张表能省很多时间。

## P28｜小结

小结六条。

递归三法则：有基例、向基例逼近、调用自身；写的时候只想两层。
