## P5｜递归：函数调用自己 + 三法则

先看最短的例子：阶乘。

n 小于等于一的时候返回一，这一支叫**基例**。否则返回 n 乘以「n 减一的阶乘」，这一支是递归调用，而且参数在往基例靠近。五的阶乘输出一百二十。

右边是三条法则，缺一不可：必须有基例，也就是不再递归的终止条件；必须改变状态并向基例逼近，否则永远到不了终点；必须调用自身。

三条里缺任何一条，写出来的就是死循环，在 Python 里表现为 RecursionError。写完一个递归函数，请对着这三条各检查一遍，这个习惯能省掉一大半的调试时间。

## P6｜相信它：只回答两个问题

这一页讲的是心法：写递归的时候**不要在脑子里展开每一层**。你展不开的，三层以后就乱了。

你只需要回答两个问题：最小的情况怎么办，这是基例；以及，假设「更小的问题已经被解决了」，怎么用它拼出当前问题的答案。

用求数组之和做例子。最小情况：空数组，和是零。假设剩下部分的和已经算好，整体的和就是首元素加上它。两行写完，结果是二十五。

但请看底下的警告：左边每一层都做切片，切片本身是线性的，套在 n 层递归里就成了 O n 平方。右边的写法用一个下标 i 代替真的切一刀，复杂度回到线性。这类「思路对但写法拖垮复杂度」的问题，在递归里特别常见。

## P7｜调用树：每一次调用画成一个节点

「相信它」是**写**递归的方法。可是要**看懂**递归到底在怎么跑：先算哪个、后算哪个、要算多久、为什么会爆栈，就得把它画出来。画出来的东西，是一棵树。

先看左边，树的几个基本词。树由节点和连接节点的边组成。最上面的 A 叫根；一条边的上端叫父节点，下端叫子节点，比如 B 是 D 和 E 的父节点；没有子节点的 D、E、F 叫叶子。根在第零层，往下依次加一。注意计算机里的树是倒着画的：根在上，叶子在下。再看 B、D、E 这三个节点，它们本身也是一棵树，叫子树。所以树的定义本身就是递归的：一棵树，等于一个根，加上若干棵子树。

右边这张表，是把递归画成树的规则：每一次函数调用，画成一个节点；最外层那次调用是根；一次递归调用，就是从父节点往下的一条边；基例不再往下调，所以是叶子；return 就是从子节点回到父节点，把结果交还给调用者。最后一行最重要：**从根到当前节点的这条路径，就是此刻的调用栈**，第二部分还会回到这句话。

这棵树叫调用树，也叫递归树。本章后面的每个例子，都会回到这棵树上。

## P8｜调用树：factorial 是一条链，fib 是一棵二叉树

左边是四的阶乘。阶乘的函数体里只调用自己一次，所以每个节点只有一个孩子，整棵树退化成一条链：四调三，三调二，二调一，一是基例，是叶子。

右边是第四项斐波那契。它的函数体里调用了自己两次，n 减一和 n 减二，所以每个非叶子节点分两个叉，长成一棵二叉树。浅绿色的都是叶子，也就是 n 小于等于二的基例。你可能已经注意到，fib 二出现了两次，这件事第三部分再细说。

底下这条规律请记住：**函数体里调用自己几次，就分几个叉**。写一次是链，写两次是二叉树；如果写在 for 循环里，就是多叉树，后面的全排列就是这种。

## P9｜执行顺序就是 DFS：一条路走到底，再退回岔路口

有了调用树，再看递归的执行顺序。

计算机不会同时算两个孩子。以斐波那契为例，fib 四先调用 fib 三，必须等 fib 三的**整棵子树**都算完、返回了，才轮到 fib 二。换句话说：沿一条路走到底，走到叶子，就退回最近的岔路口，再换下一条路。

这种走法叫深度优先搜索，英文缩写 DFS，就像走迷宫。看左边蓝圈里的数字：先走 A、B、D；D 是叶子，退回 B，走 E；B 下面都走完了，退回 A，再走 C 和 F。所以 DFS 的访问顺序是 A B D E C F。作为对比，广度优先搜索 BFS 是一层一层地走，顺序是 A B C D E F。

所以说，**递归就是天然的 DFS**。看右边这几行代码：调用一次 dfs child，就是往下走一层；函数返回，就是退回上一层，回到岔路口去处理下一个孩子。走到 D 的时候，调用栈里依次是 dfs A、dfs B、dfs D，正好就是从根到 D 的路径。

## P10｜打印调用树：让程序自己把调用树打出来

调用树不只是画在纸上的，可以让程序自己打出来。

办法很简单：给递归函数加一个深度参数 depth，每次进函数，先按深度缩进，打印出参数；往下调用时，深度加一。

算第四项斐波那契，输出是这样的：fib 四顶格，fib 三缩进一层，它下面的 fib 二和 fib 一缩进两层，最后回到一层缩进的 fib 二。对照前面那棵树：**缩进越深，就是树里越深的一层；按行往下读，就是 DFS 走过节点的顺序**。

递归写不对的时候，这是最快的调试手段。看到同一个参数被打印了好几次，也就是重复的子树，就该上记忆化。

## P11｜两个数看穿一个递归：时间看节点数，栈深看树高

画出调用树以后，分析一个递归，只需要看两个数。

第一个，**时间约等于节点数乘以每个节点的工作量**。注意这里的工作量只算节点自己做的事，不算它的子调用，子调用是别的节点。

第二个，**栈深等于树高加一**。同一时刻栈里只有一条从根往下的路径，所以最大栈深，就是最深那条路径上的节点数；根算第零层，节点数正好比树高多一。树越高，越容易爆栈，这是第二部分的主题。

下面这张表，把本周的例子放在一起：阶乘和下标版的数组求和，都是链，节点数和栈深都是线性的。朴素斐波那契是二叉树，有重复子树，节点数是指数级，栈深却只有 n 减一。汉诺塔是满二叉树，不算 n 等于零的空调用，二的 n 次方减一个节点，栈深是 n。全排列是决策树，节点数小于 e 乘 n 的阶乘。后面讲到每一个，都会回来对这张表。

最后回答前面留下的问题：切片版的数组求和，为什么是 n 平方？它和下标版一样，也是 n 加一个节点的链，节点数没变；变的是每个节点的工作量，每次切片都是线性的。线性个节点乘以线性，就是 n 平方。

## P12｜任何递归都能改写成迭代（用显式栈）

任何递归都能改写成迭代，反过来也一样。

这一页用进制转换做例子：左边是递归版，n 小于基数时直接返回那一位数字，否则先转换 n 整除基数的部分，再接上最后一位，贴近数学定义。右边是迭代版，用一个**显式的栈**，不断取余压栈，最后反转拼接。两个版本把二百三十三转成十六进制，都得到 E 九。

取舍：递归代码短、更贴近问题的数学定义；迭代没有深度限制、常数更小。

经验法则：能写成简单循环的，就别用递归。递归是用来处理「问题的结构本身就是递归的」那类题，不是用来炫技的。

## P14｜每次函数调用都压入一个栈帧

看这张图，三的阶乘的调用过程。

调用三的阶乘时，压入一个栈帧；它调用二的阶乘，再压一个；再调用一的阶乘，又压一个，到达基例。然后开始返回：一的阶乘返回一，弹出；二的阶乘返回二乘一等于二，弹出；三的阶乘返回三乘二等于六，弹出，栈空。

每个栈帧里放着这一层的参数、局部变量和返回地址。

所以一句话：**递归就是在用系统栈**。对照第一部分的调用树来看：栈里装的，始终是从根到当前节点的那条路径；往下调一层就压一帧，return 一次就弹一帧。最大栈深，就是最深那条路径上的节点数。栈的空间是有限的，树太高，栈就溢出。后面几页讲这件事在今天的 Python 上究竟是什么样。

## P15｜递归深度限制：其实有两道墙

先看代码：sys 点 getrecursionlimit 默认是一千；OJ 上深递归常见的写法是把它设成一左移二十。

但很多人不知道，递归深度其实有两道墙。

墙一，是解释器自己数的嵌套层数。撞上去抛 RecursionError，**看得懂**，setrecursionlimit 管得到。

墙二，是**C 调用栈**，主线程通常八兆。撞上去是段错误，进程直接死，没有任何可读的信息；setrecursionlimit **管不到**。

墙一本来是设在墙二前面的护栏，让你在真正撞墙之前先收到一个能看懂的异常。把限制调大，等于把护栏挪远，而墙二一动没动。调大递归限制不是免费的，它换来的可能是更难诊断的崩溃。

## P16｜CPython 3.11 之后，两道墙的位置变了

这两道墙的位置，在新版 CPython 里变了。

两处变化：三点十一起，Python 函数调 Python 函数在解释器主循环内部展开，不再占用 C 栈；三点十二又给确实要走 C 的递归另设了一道上限，这道上限 setrecursionlimit 管不到。

看本机实测，CPython 三点十二点三、Linux，已经把递归限制调大。第一行，**纯 Python 递归，三十万层照跑**，连三十二 KB 的线程栈都够用。第二行，递归**穿过 C 代码**，比如用了 lru_cache，**三千三百三十一层就封顶**，抛 RecursionError；把线程栈加到六十四兆也没用。

请把这两行当成某个环境下的实测值，**不是语言规范**。换版本、换评测机都可能不同，这恰恰是不该依赖它的理由。

## P18｜二分探测：纯递归 vs 穿过 lru_cache

这就是探测函数。下界一、上界十万，每次取中点去跑递归函数：跑通了就把下界提到中点，抛 RecursionError 就把上界降到中点减一。这是二分答案的写法，后面的课会反复见到。

被测的有两个：plain 是最朴素的递归，每层返回一加上 f 的 n 减一；cached 是同一个函数，只多加了一个 lru_cache 装饰器。

一个装饰器，深度差了三十倍。

## P19｜那段线程写法还要不要写

你在网上常会看到这样一段写法：把递归代码包进 main 函数，用 threading 点 stack_size 把线程栈设成六十四兆，再开一个新线程跑它。它加大的是新线程的 C 栈，也就是把墙二往后推。

它还有没有用？看表。CPython 三点十及以前，任意递归，有效，因为每层调用真的压 C 栈。三点十一以后的纯 Python 递归，没必要，本来就不吃 C 栈。穿过 C 的递归，比如 lru_cache 那类，没用，实测加到六十四兆仍是三千三百三十一层。

所以请记住：**别把它当护身符**。它能不能救你，取决于评测机装的是哪个版本、你的递归是哪种形状，这两件事你都控制不了。

## P20｜唯一与版本、评测机都无关的做法：改写成迭代

那么深递归的题到底该怎么写？答案是：改写成迭代，用显式栈。

上面是递归版，求深度；下面是同一件事的显式栈版本，自己拿一个列表当栈，弹出一个数，不为零就计数加一，再把它减一压回去。它的深度只受内存限制。

两个结果对照：深度三千时两者一致；而一百万层，只有显式栈那一版能跑出来。

底下是本部分的结论：**深递归题的可靠解法只有一个，就是显式栈**，它既绕开墙一，也绕开墙二。setrecursionlimit 和加大线程栈都是看运气的补丁，而且它们失败的方式，段错误或者运行错误，恰恰是考场上最难诊断的那种。

## P21｜进程的虚拟地址空间：栈从哪儿来？

最后看一眼整张内存图：栈从哪儿来。第十三周还会回来。

从高地址往低地址：内核区；**栈**，放函数调用帧，向下增长；**堆**，放动态分配的对象，向上增长；再往下是全局和静态数据；最下面是代码段。

栈和堆的区别：栈自动管理，容量小，通常八兆，深递归撑爆的就是它；堆由手动或者垃圾回收管理，容量大，Python 的列表、字典都在堆上。

「虚拟」这个词的意思是：每个进程都以为自己独占整个地址空间，实际由操作系统加上内存管理单元映射到物理内存。这也是为什么两个程序可以同时用同一个地址而互不冲突。

## P24｜重叠子问题：fib(5) 的调用树

这是算第五项的调用树。

算五要算四和三，算四又要算三和二。数一数：**三被算了两次，二被算了三次**。问题规模越大，重复越多，整体是指数级。

这个现象有个名字，叫**重叠子问题**。它是第十周动态规划的两个前提之一，现在先记住这个词。

底下这句话请记住：**记忆化，就是每棵子树只算一次**。第一次算完 fib 三，就把结果记下来；以后再遇到 fib 三，直接返回，不再往下长。这样整棵树被剪得只剩最左边那条链，每个右孩子都变成查表就返回的叶子，节点数从指数级降到线性。下一页就是三种修法。

## P25｜三种修法：记忆化 · 迭代递推 · 自底向上填表

同一个问题，三种修法，都是线性。

修法一，记忆化：在函数上加一个 lru_cache 装饰器，算过的结果自动存下来。

修法二，迭代递推：两个变量滚动往前推，线性时间、常数空间。

修法三，自底向上填表：开一个数组，从小到大填。这就是动态规划的标准形状，第十周会正面讲。

三者算第五十项，结果都是一百二十五亿多，完全一致。

最划算的一行代码就是这个装饰器，它把指数降成线性。但有两个代价：参数必须可哈希，不能传列表；缓存会一直占内存。另外别忘了，它正是前面说的「穿过 C 代码」。作业里的 Pell 数列是同一个套路。

## P26｜第一部：04147 汉诺塔问题

第一部，零四一四七，汉诺塔。题意：把 n 个盘子从 A 柱移到 C 柱，借助 B 柱；每次只能移一个，大盘不能压在小盘上。

它的解法是「相信更小的问题已经解决」的最好示范。三步：把上面 n 减一个盘从 A 借助 C 移到 B；把最大的第 n 个盘从 A 移到 C；再把那 n 减一个盘从 B 借助 A 移到 C。

代码就是这三步，一行一步，加上一个 n 等于零的基例。第一步和第三步，你不需要知道具体怎么移，假设它们已经解决了就行。

## P27｜跑一遍 hanoi(3, ...) + 移动次数公式

跑一遍三个盘子：一共七次移动，下面列出了每一步，哪个盘子从哪根柱子到哪根柱子。

移动次数的递推是：T n 等于二倍的 T n 减一，再加一；T 一等于一。解出来是**二的 n 次方减一**。右边用一左移 n 再减一来算，一到七个盘子分别是一、三、七、十五、三十一、六十三、一百二十七。

最后给你一个指数复杂度的实感：传说中六十四层的汉诺塔，需要二的六十四次方减一次移动，大约一点八乘十的十九次方。每秒移动一次，需要大约五千八百五十亿年。

这就是为什么第四周那张表里，指数级后面画的是叉。

## P28｜汉诺塔：调用树是一棵满二叉树

把汉诺塔的调用树画出来。每次调用有两个孩子，就是三步里的第一步和第三步，所以它是一棵**满二叉树**。每个节点标的是盘数，以及从哪根柱移到哪根柱；n 等于零的空调用省略了。

从这棵树上，两件事一眼可见。

第一，每个节点恰好做一次移动，就是三步里的第二步。所以**移动次数等于节点数**：一加二加四，等于七。n 层的满二叉树有二的 n 次方减一个节点，和前一页递推式解出来的结果一致。

第二，看蓝圈里的数字，这是移动的先后顺序。每个节点都是先处理左子树，再做自己那一次移动，再处理右子树。从左到右把节点读一遍：一号盘 A 到 C，二号盘 A 到 B，一号盘 C 到 B，三号盘 A 到 C，一号盘 B 到 A，二号盘 B 到 C，一号盘 A 到 C，正好就是程序输出的那七行。这种左、根、右的访问顺序，叫**中序遍历**，以后学二叉树还会遇到。

## P29｜从调用树到决策树

进入第二部全排列之前，先换个角度看树。斐波那契和汉诺塔的调用树，形状是由公式决定的：F n 永远拆成 F n 减一和 F n 减二。全排列不一样，每一层要**做一次选择**：第一个位置放谁，第二个位置放谁。这时候，调用树换个名字，叫**决策树**。

先看右边一个生活里的例子：出门穿衣，先选上衣，白 T 恤或衬衫；再选裤子，牛仔裤或短裤。根节点表示还没开始选，第一层表示上衣选好了，第二层表示全部选好了，一共二乘二等于四个叶子。

记住下面这四个对应：节点是做到一半的状态，边是一次选择，叶子是全部选完，从根到叶子的一条路径，就是一个完整方案。

和第一部分的调用树对一下：节点仍然是一次函数调用，边仍然是一次递归调用，执行顺序仍然是 DFS。**只多了一件事**：沿着边往下走时，要把这一步选了什么记在一个共享的 path 里；退回来的时候，得把它擦掉。

## P30｜全排列的决策树：叶子就是答案

再来看全排列本身。一二三的决策树是这样的：根是空列表，表示还什么都没选；第一层选第一个数，有三种；第二层在剩下的数里再选一个，三乘二等于六种；第三层只剩一个数，三乘二乘一，还是六种。

最底层的六个叶子，从左到右，恰好就是六个排列。

所以我们要做的，就是用 DFS 把这棵树从左到右走一遍。path 就是从根到当前节点的路径：调用 dfs 往下一层，path 点 pop 退回一层；走到叶子，也就是 path 的长度等于 n 的时候，就把 path 的拷贝存进结果。下一页的代码，就是在这棵树上做 DFS。

## P31｜第二部：02748 全排列

第二部，零二七四八，全排列。它是**回溯模板的原型**，下一周整套回溯都建立在这一页上。

结构是：如果路径长度等于 n，就收下一个答案；否则枚举每个还没用过的元素，标记为已用、加入路径、递归，然后**撤销**。一二三的全排列输出六个结果。

## P32｜为什么是 O(n · n!)：数一数节点

上一页说复杂度是 n 乘 n 的阶乘，这一页来解释它是怎么来的。关键是数清这棵决策树一共有多少个节点。

从叶子往上看。叶子有 n 的阶乘个；往上一层少选了一个数，节点数除以一；再往上，再除以二；再往上，再除以三。n 等于三时，就是六、六、三、一，合计十六个节点。一般地，节点总数等于 n 的阶乘，乘以括号里的一加一，加二的阶乘分之一，加三的阶乘分之一，一直加到 n 的阶乘分之一。

括号里这个和，无限加下去正好等于自然常数 e，约二点七一八；只加到 n 的阶乘分之一，就一定小于 e。所以节点总数小于 e 乘 n 的阶乘，只是叶子数的常数倍。验算一下：六乘二点六六七等于十六，确实小于 e 乘六，约十六点三。

每个节点做多少工作？内部节点要把 n 个数循环一遍，而 used 数组的判断是常数时间；叶子要拷贝 n 个数。所以每个节点都是 O n，总时间就是 n 乘 n 的阶乘。

最后提醒一句：如果像 LeetCode 上常见的写法那样，用 x not in path 来判断是否用过，这一步本身就要扫描整个 path，总时间就变成 n 方乘 n 的阶乘。上一页的代码用 used 数组，正是为了把这个判断降到常数时间。

## P33｜回溯 = DFS + 撤销：显式与隐式

回溯和 DFS 是什么关系？一句话：回溯，就是在决策树上做 DFS，再加上退回时撤销选择。DFS 讲的是遍历顺序；回溯讲的是状态怎么维护。

左边是我们的写法：整个搜索只用一份共享的 path 和 used，往下走时修改，退回来时手动 pop、手动清掉标记，这叫显式回溯。

右边是另一种写法：每层把 p 加上 x，生成一个新列表传下去，代码里根本没有 pop。这并不是没有回溯，而是撤销这一步不用自己写：调用方手里的 p 从来没有被改过，下一层返回时，它的栈帧连同那个新列表一起丢掉，状态自然就恢复了。回溯隐含在参数传递里，所以叫隐式回溯。代价是每层都要复制一次列表。

由此得到一条规律：通过参数传值的状态，比如 i 加一、新建的列表，返回后自动恢复；共享并且原地修改的状态，比如 path 和 used，必须手动撤销。

## P35｜LC 78 子集：每个元素选或不选

最后补充一道和全排列配套的题：力扣七十八，子集。

子集的决策更简单：对每个元素，只有选和不选两种。决策树的每一层决定一个元素，左边不选，右边选。三个元素就有二的三次方，八个叶子，正好是全部八个子集。

看代码。backtrack 带一个参数 i，表示现在要对第 i 个元素做决定。i 等于 n 时到达叶子，收下 sol 的拷贝。否则先走不选的分支，直接递归 i 加一；再走选的分支：把它加进 sol，递归，然后 pop 撤销。

## P37｜分治：分 → 治 → 合

分治的三步：分、治、合。表里四个例子横向对比。

归并排序：对半切，合并两个有序表，O n log n。

快速排序：按枢轴划分，**不需要合并**，平均 O n log n。

快速幂：指数减半，合的时候相乘，O log n。

## P38｜快速幂：指数减半

快速幂，用 O log b 的时间求 a 的 b 次方。

思路：指数为零返回一；否则先递归算出 a 的 b 整除二次方，记作 half，自乘一次；如果 b 是奇数，再乘一个 a。可选地每一步取模。

输出：二的十次方是一千零二十四；三的一百次方对十亿零七取模，手写版和内建版结果一致。

右边这句很重要：Python 内建的 pow 传第三个参数，就是快速幂，考试直接用它。手写一遍，是为了看懂「指数减半」这个分治思路。

## P39｜二分查找：只保留半边

二分查找，每次只保留半边，O log n。

上面是最基础的一版：在闭区间里找目标，相等就返回下标，小了往右，大了往左，找不到返回负一。

下面是更常用的形态：求第一个大于等于目标的位置，也就是 lower bound。区间取左闭右开，小于目标就把左边界推到中点加一，否则把右边界收到中点。它和标准库 bisect 点 bisect left 的结果一致。

模板选择：lo 小于 hi、hi 等于 mid 这一版，不会死循环，也不会漏边界，建议**只记这一版**。需要「最后一个小于等于目标的位置」时，用 lower bound 对目标加一的结果再减一。改写比重写安全。

## P40｜最大公约数：03248 辗转相除

零三二四八，最大公约数，辗转相除，一行：b 为零就返回 a，否则递归求 b 和 a 除以 b 的余数的最大公约数。

顺带给出最小公倍数：a 先除以最大公约数，再乘以 b。代码里是**先除后乘**，避免中间结果过大。在 Python 里这不算问题，但在 C 加加里会溢出，这是个好习惯。十二和十八的最大公约数是六，四和六的最小公倍数是十二。

为什么这样做是对的？a 和 b 的公约数集合，与 b 和 a 模 b 的公约数集合**完全相同**。因为 a 等于 k 倍的 b 加上 r，任何同时整除 b 和 r 的数也整除 a。所以问题可以一直缩小，直到余数为零。
