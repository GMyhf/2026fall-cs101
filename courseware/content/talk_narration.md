## P1｜封面

各位同学好，这是一次课堂分享，题目是：用 Agent 快速做科研。

我把最近怎么为一篇 A 类会议论文做准备，原样讲给大家。整条线是这样的：平时在 GitHub 上积累仓库；用 CCF 会议列表加 Agent 查新，找到能投的题目；选好 Agent，准备闭源 API 和开源模型要用的 GPU；用 Tailscale、CLab 和中转机把基础设施搭起来；在过程中看 status、看 thinking、看日志来指导 Agent；再找发过 A 类的人合作；最后至少落地一篇 arXiv 预印本。

最后还会讲讲平时要做什么，以及为什么在 Agent 时代，还要学数据结构。

---

## P2｜开场：这一讲回答三个问题

这一讲回答三个问题。

第一，题目从哪来？Agent 很强，但差最后一公里，就是想法。想法来自平时在 GitHub 上一个个仓库的积累，再让 Agent 去和会议主题做匹配、做查新。

第二，实验靠什么跑？靠订阅的闭源大模型，加上自己能拿到的 GPU 跑开源模型。机器、网络、服务，都是平时一点点搭、一点点帮人换来的。

第三，人在里面做什么？盯进度、看 thinking、在它犯蠢的时候点拨一下；再去找发过 A 类的人讨论。这也是为什么还要学数据结构。

一句话概括：积累、匹配、资源、指导、合作。

## P3｜为什么讲这个：现在是「许愿式编程」

为什么讲这个？因为现在是「许愿式编程」。

我虽然在教大家算法和编程，但其实自己已经很少写代码了，因为 Agent 很好用。只要有想法，就去开一个仓库，把想法说给它，让它去做。

大家都是研究生，对发文章肯定感兴趣。所以我把最近几天正在做的事原样讲一遍：从零开始，为 CCF A 类会议 ACL 准备一篇投稿。

有一种说法是「基本上不需要导师了」。这是夸张，意思是：只要有想法、有资源，大部分体力活和很多脑力活都能交给 Agent。但后面会看到，想法、资源、判断、合作，仍然要靠人。

## P4｜PART 1　找题目

第一部分，找题目：积累仓库，选会议，再让 Agent 做匹配和查新。

## P5｜第一步 · 积累：有想法就在 GitHub 开一个仓库

第一步是积累：有想法就在 GitHub 上开一个仓库。

往里面「灌」东西：工程项目、以前随手试过的想法、甚至小游戏，五花八门都行。仓库可以是 public，所有人可见；也可以是 private，只有自己能看。投稿前的工作，一定要开 private。

放在 GitHub 上还有一个好处：本地丢了，它还在。日积月累，仓库越来越多，这就是后面找题目的原料。

怎么让仓库变多？靠合作者，也就是 collaborator。private 仓库可以把合作者的 GitHub 账号加进来，这是合作的起点，这次我就把学生加进了论文仓库。本科课程的大作业做不下去时，我也让同学把我加成 collaborator，用最好的 Agent 帮他做。最近这样又多了三个仓库。不见得马上有用，但说不定什么时候就有用了。

---

## P6｜第二步 · 匹配：选会议，看 CCF 推荐列表

第二步是匹配。先选会议，看 CCF 推荐列表。

CCF 每年发布推荐列表，现在是二零二六版，分 A、B、C 三类。博士生毕业通常要求至少两篇 A 类。为什么投会议？因为审稿周期比期刊短，适合快速做科研。

举个例子，ACL 是自然语言处理方向的 A 类会议，截稿大约在一月初。现在是十一月，还来得及。

难点在于：有时间，但没想法。Agent 现在特别强，但差最后一公里：想法从哪来？看起来挺好，想试试，可是没想法，就不知道怎么办。

---

## P7｜第二步 · 匹配：把 GitHub 权限交给 Agent

我的做法是：把 GitHub 的访问权限交给 Agent，问它：我想投这个会，能投什么？

它做了三件事。第一，扫仓库：把我所有仓库扫一遍，盘点做过哪些项目、手头有哪些数据集。第二，做匹配：和会议的征稿主题逐一比对，提出能投的 topic。第三，查新：做相关工作调研，看这个想法是不是已经有人做完了，因为 A 类会议要求 novelty。

结论是：还可以做；你手头恰好有这份语料，别人好像还没有。这三步，过去都是博士生最累的活，读前沿文献、做 survey，现在交给了 Agent。

要注意，它给的 topic 下面附了很多前提条件：要先做一批实验，确认条件都成立，才值得投；不成立就投不了。所以这几天，正好大家考期中，我一直在跑实验。

---

## P8｜第三步 · 工具：选 Agent，能用第一档就用第一档

第三步，选 Agent。原则是：能用第一档，就用第一档。

第一档是 Anthropic 的 Claude，也就是 Claude Code，公认最聪明。缺点是国内不在服务地区，要有合规的使用途径；订阅大约每月两百美元。第二档是 OpenAI 的 Codex，相对好获得，但和第一档差距明显。第三档是国产模型，比如学校提供的 Qoder，里面有 Kimi、GLM、DeepSeek 等，能用，但很累：经常做错，还要用前面的模型 review 再改，它不指导你，还经常添乱。

Top 1 的 Agent 有个特别好的地方：它其实在指导你。回答完一个问题，它会建设性地提几条后续建议，你从中选、不停地追下去，这就是指导。

我现在的组合是：Claude 做主力，Codex 和同学合租分摊费用，学校的 Qoder 做备用。Qoder 每月有三千 credits，当月用不到三分之一，可能会被收回。

## P10｜第四步 · 资源：顶会实验，两类模型都要跑

第四步是资源。顶会的实验，两类模型都要跑。

一类是闭源模型，通过订阅或 API 付费使用，是当前最好、大家都在用的模型，投顶会肯定要用它们跑。

另一类是开源模型。顶会对实验要求高：数据集多、角度多、模型也多。开源模型要 GPU，这是学生最大的门槛。

苹果的统一内存能不能顶上？我试过让 Agent 把任务搬到六十四 GB 的 Mac Studio 和一百二十八 GB 的 MacBook Pro 上。能迁，但它估算：在四零九零 D 上一两个小时的小任务，在 Mac 上要一到三天。所以，有 N 卡还是用 N 卡。

## P11｜第四步 · 资源：GPU 是怎么来的

GPU 是怎么来的？靠平时帮人。

今年七月，一位老师有台多卡机器没地方放，我帮他找了地方，然后就忘了要账号。

最近机房路由器坏了，他的学生来找我：机器出不了网，他们也想赶 ACL。

我想起有块闲置了两年的 Netgear 无线网卡，就借给了他。Linux 上没有现成驱动，那位同学下了源码自己编译，当天晚上就弄通了。

我顺势要了个账号：五块四零九零 D，每块四十八 GB。其中一块满负荷就会宕，我用另外四块。

大家平时能帮忙就尽量帮一下，说不定什么时候就有回报。机会就这样来了：目标有了，是 ACL；想法有了，是 Agent 匹配出来的；资源也有了，是四块卡。

## P12｜第四步 · 资源：共享 GPU 的分寸

共享 GPU 要有分寸：不跟人抢，用人家空闲的时候。

那台机器上别人的权限比我高。有天早上九点多，四块卡全被占了，我的任务跑不了。等了三个小时，发现对方只是起了个 DeepSeek 推理服务把卡占着，实际没在算。我写信问了一下，对方确实没在跑任务，就撤了下来。之后我就抓紧在人家空闲的时候跑。

原则有三条：不能跟人抢，公共资源先到先用，别人优先；发现占而不用，礼貌地问一句；坏卡之类的问题，要告诉管理员。

## P13｜第五步 · 基础设施：用 Tailscale 把机器连成一张网

第五步是基础设施。我用 Tailscale，把手头的机器连成一张虚拟内网。

这张网里有：美国同学家的一台机器，主力 Agent 跑在上面；成都的腾讯云，做国内中转；北大 CLab 的虚拟机，跑 Canvas 等服务；办公室的 Mac Studio 和一台 Windows 机器，二十四小时不关；还有上课用的 MacBook、一百二十八 GB 的 MacBook Pro，以及同事、朋友、家人的机器。

能帮别人就帮：同事的机器出了问题，我就让他加入我的 Tailscale，帮他调好。

## P14｜第五步 · 基础设施：免费的校内云，北大 CLab

再介绍一个免费的校内云：北大 CLab。

它是北大 Linux 俱乐部做的、计算中心支持的，凡是有校园 ID，都免费给一台云虚拟机，默认大约四 GB 内存、一百 GB 固态硬盘。我读手册时发现，老师可以申请更多资源，申请之后给了三十二 GB 内存，外加五百 GB 固态硬盘。

本课程的 Canvas 教学系统、评测题库等都跑在上面，稳定，不用自己维护。

为什么要自己搭教学系统？因为新学院还没有教学管理系统；作业发邮箱也不可靠，学校邮箱会把部分邮件当成垃圾邮件，而且没法逐个下载批改。

域名也靠合作：自己申请有周期，每年还要交钱；我请一位熟悉的老师，在他的顶级域名下给我加了几个子域名。不要单打独斗。

## P15｜第五步 · 基础设施：Canvas 为什么慢，一个图上的路径问题

开学初，大家说访问 Canvas 很慢，为什么？这其实是一个图上的路径问题。

之前，校外同学访问校内的 CLab，Tailscale 默认给出的路径绕到了国外的中继。之后，我加了一台国内的小云服务器做中转，路径变成：校外同学，到成都腾讯云，再到校内的 CLab。

两点要通信，先得找一条可达路径，第七章「图」讲的就是这个。路径选错了，能通，但很慢。

这台中转机是腾讯云成都的，两核两 GB、四十 GB 硬盘，大约一百六十八元一年。它只负责转发，服务不在它上面，所以配置可以很低。

## P16｜第五步 · 基础设施：让 Agent 二十四小时跑

怎么让 Agent 二十四小时跑？要有不关机的机器，还要能断点续传。

我有好几台不关机的机器：办公室的 Mac Studio、成都中转机、CLab、一台 Windows 机器，还有美国同学帮忙维护的机器。主力 Agent 所在的是同学家里一台旧的小主机，满负荷时偶尔重启，一个月一两次。我做了定时探活监控，宕了就微信请他处理，中间有十二三个小时的时差，这种事很费人情。

我走到哪都带着电脑，因为手机屏幕太小；电脑上一直开着一个 terminal，远程连着。

重启了也不怕：在 Claude Code 里输入斜杠 resume，会列出之前的 session，选一个继续，相当于断点续传。要点是：任务跑在远端常开的机器上，本地只是一个窗口。

## P18｜第六步 · 指导：并行任务一多，要常去敲一句 status

第六步是指导。并行任务一多，就要常去敲一句 status，问它：我布置的这一堆，现在都跑成什么样了？

它会报告：哪块卡上的任务还要七个小时，哪三个模型第二节课能跑完，哪个闭源模型已经停了。不进去看，根本不知道一个模型已经停工：昨天 Codex 合租那边本周额度用完了，要等今天四点五十自动重置。

还有，公共 GPU 空了，Agent 不会自己随便起新任务，这是对的。所以我醒着时把任务布满；早上醒来发现卡闲了，就让它赶紧找任务。它还会预估完成时间：下午三点多的飞机，在机场还能看一眼，飞机上就管不了了。

输入也不必讲究。远程切中文输入法麻烦，我就直接打英文单词，拼错几个字母它也懂；但别打拼音。

---

## P19｜第六步 · 指导：内存放不下，就放外存

它怎么扛住这么多任务？

上下文窗口是有限的，订阅里最大的大约一百万 token，并行任务一多就装满了。还有内容污染：它能读到我 GitHub 上所有的项目，容易串。

我看它的 thinking 发现：它给每个任务写一个独立的日志文件，需要时再去读。

这就是数据结构：主存，也就是上下文，放不下，就放到外存，也就是日志文件，按需读取。这正是第九章外排序、第十一章索引的思路。

另外，Agent 最后只给一个 summary，中间过程你可能不知道。看到有价值的输出，我就随手丢进微信的文件传输，积累素材，以后有新想法时回去翻。

---

## P20｜第六步 · 指导：看 thinking，在它犯蠢时点拨一下

有时间的时候，我会盯着它的 thinking 过程，不只看最终结果。有时你会受到启发；有时会发现它也很蠢，包括 Claude。这时就需要你点拨它一下。

分工是这样的：Agent 做扫描、调研、写代码、跑实验、排版、翻译，这些体力活和大量脑力活。人来给方向、看过程、判断对错、点拨；资源闲了来布置任务；再去找人讨论。

这是双方的配合，而点拨靠的，是你的基础知识。

## P21｜第七步 · 合作：找发过 A 类的人一起做

第七步是合作。没中过 A 类，就没有投稿经验，要找师兄师姐、导师，或者任何发过 A 类的人。

坦白说，我自己也没以第一作者中过 A 类。这次我找的是我的一位硕士生。他研一在计算中心当学生助理，接触到了 GPU 和大模型；研二出去实习，目标很明确，要找能指导发论文的 mentor；投稿一直被拒，直到今年才开始中，一中就是两篇 A 类。在我们那里，博士生两篇就能毕业。

我把想法和 Agent 跑出来的东西都给他看，他给了反馈。有的反馈我看不懂，怎么办？再交给 Agent，它又提出新的实验，GPU 又有活干了。

GPU 一直在跑，但有时我也不知道该让它跑什么，这时就要和人讨论。

## P22｜第八步 · 落地：至少落地一篇 arXiv 预印本

第八步是落地：即使会议不中，至少落地一篇 arXiv 预印本。

一是中英双份：让 Agent 中英文各出一份，我看中文找问题，再让它改英文。二是标准模板：会议和 arXiv 都有标准格式，让 Agent 来排版。三是找人背书：第一次投 arXiv，需要相关领域的人做 endorsement；我七月中旬投的，大约一个月后才上线。四是持续迭代：预印本可以不停地改，差不多了再投正式会议。

像这次的 ACL 二零二七：中了最好；不中，也有一篇预印本，GitHub 上又多一个仓库，继续滚动。

## P24｜平时：维护圈子、积累简历

先说圈子。为人处事包容一点，能帮就帮，合作者就多了。这次的 GPU、域名、arXiv 背书、Agent 的使用途径，全是靠人。还要锻炼身体，学校球馆二十四小时开放。也要关注学校门户，上面常挂国际交流项目，看不到就错过了。

再说简历。研究生阶段就是在积累简历，毕业时不能只有各科成绩。毕业大致两条路：去高校当老师，或者去企业做研发。筛简历主要看成绩和科研：成绩过了三点三左右就差不多；最被认可的是文章，没有文章就看实习。

还有件趣事：有一年，好几个同学在同一家公司实习，那家公司是他们一位同学开的，而那位同学的绩点恰恰最低。

## P25｜回到这门课：为什么还要学数据结构

最后回到这门课：为什么还要学数据结构？

今天遇到的事，背后都有数据结构和算法。Canvas 访问慢、加国内中转，背后是图上的可达路径与路径选择，第七章「图」。上下文窗口装不下并行任务，背后是主存放不下就放外存、靠日志按需读取，第九章和第十一章的外排序与索引。多块 GPU、多个任务、预估完成时间，背后是队列与调度，第三章。Agent 扫全部仓库做匹配，背后是检索与匹配，第四章字符串和第十章检索。

Agent 很强，但你得给它一点指导。我们平时上课，就是在积累这些点拨 Agent 用的基础知识。

---

## P26｜小结

小结五点。

第一，积累：有想法就开 GitHub 仓库；投稿前用 private；靠 collaborator 合作。

第二，匹配：从 CCF 列表选会议，让 Agent 扫仓库、匹配主题、查新，得到 topic 和前置实验。

第三，资源：用最好的 Agent；闭源 API 加开源模型的 GPU；平时帮人，换来机会。

第四，指导：常看 status、看 thinking、及时点拨；资源闲了人来布置；随手记录。

第五，合作：找发过 A 类的人讨论；预印本先落地；维护圈子，积累简历。
