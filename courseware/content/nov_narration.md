## P7｜T1 双重回文

T1，双重回文，题号 E 三一五二九。

一个正整数，如果它在十进制和二进制、不带前导零的写法下都是回文，就叫双重回文数。给定 n，最大十的六次方，输出一到 n 里双重回文数的个数，以及最大的那一个。

样例一，n 等于五，答案是三个，最大是五。样例二，n 等于一百，答案是七个，最大是九十九。

直接枚举就够了。十的六次方个数，每个判两次回文，Python 也来得及。还能再省一半：偶数的二进制末位是零，而最高位一定是一，所以偶数不可能是二进制回文，只枚举奇数就行。

C 加加不用转字符串，按 base 进制把数倒过来，看是否等于自己。n 等于十的六次方时，答案是十九个，最大的是五十八万五千五百八十五。

## P8｜T1 参考代码

C 加加版写一个 pal 函数：t 从 x 开始，每次除以 base，y 等于 y 乘 base 再加上 t 模 base，这样就把 x 按 base 进制倒了过来，最后比较 y 和 x 是否相等。主函数里 i 从一开始、每次加二，十进制和二进制都是回文就计数，并记下当前的 i。

Python 版更短：d 是十进制字符串，b 是 bin 去掉前缀之后的二进制串，两个都等于自己的反转，就计数。

签到题，务必一次通过。

## P9｜T2 图书馆选座

T2，图书馆选座，题号 E 三一五三零。

n 个座位排成一行，用零一串 s 表示初始是否有人。m 位同学依次进来，每人选编号最小、而且左右相邻座位都空着的空座位坐下；没有这样的座位，就离开。n 和 m 都不超过两千。输出坐下的人数，和最终的零一串。

照题意模拟，每人从头扫一遍，O n m 能过。但再想一步，可以做到 O n。

关键观察是：座位只会越坐越满。一个座位现在不能坐，以后也不可能变得能坐；某人坐在 i 之后，i 加一也不能坐了。所以下一位同学的座位一定在上一位的右边。于是从左扫到右，能坐就坐，坐满 m 人就停。

注意边界：Python 里 s 负一不会报错，它会悄悄读到最后一个座位。所以第一个座位的左边要单独判断。

---

## P11｜T3 箭头迷阵

T3，箭头迷阵，题号 M 三一五三一。

n 乘 m 的网格，格子总数不超过二十万，每格一个箭头，上下左右之一。从某格出发，一直按箭头走，如果最终走出了场地，就说这一格可以逃出。题目特别说明，途中可以先绕圈。要统计能逃出的格子数。

样例一是二乘二的网格，答案是二；样例二是三乘三，答案是五。

这道题要想清楚一点：每一步往哪走是确定的。「途中可以先绕圈」只是说路线会拐来拐去；一旦真的回到走过的格子，就困在环里，永远出不去了。

所以每格的结论只有两种：能逃出，或者逃不出。这个结论可以记下来，后面的路线走到它时直接复用。

---

## P12｜T3 四种状态 + 显式路径

具体做法是给每格四种状态。

零是未访问：走到这里时标成一，加入当前路径 path，继续往前走。一表示在当前路线上：如果又走到它，说明撞上了本条路线，成环，结论是逃不出。二是能逃出，三是逃不出：走到这样的格子，直接接上已知结论。如果下一步出界了，结论就是能逃出。

路线停下之后，把 path 上的格子全部标成这个结论。每格只走一次，总复杂度 O n m。

为什么不写递归？如果一整行都是 R，路线长度可以到二十万，递归会撞上深度限制，得配合 threading 加大栈，这是第八周讲过的。显式维护 path 的循环是同一个算法，但没有这个问题。

## P15｜T4 牌堆魔术

T4，牌堆魔术，题号 M 三一五三二。

n 张牌叠成一摞，n 最大二十万。重复 n 轮：先把顶牌移到底，再翻开顶牌并拿走。要求翻开的顺序恰好是一、二、一直到 n。求初始牌堆从上到下的顺序。

样例一，n 等于四，答案是四、一、三、二。

已知结果求开头，就倒着做，把每一步撤销。i 从 n 倒数到一：撤销「翻开顶牌 i」，就是把 i 放回牌顶；撤销「顶牌移到底」，就是把底牌移回牌顶。两端都要进出，用双端队列，总共 O n。

用 n 等于四验算一下：先放四；再放三；然后变成三、二、四；最后得到四、一、三、二，和样例一致。

注意，如果用 list 的 insert 零，每次是 O n，总共 O n 方，会超时。

## P16｜T4 参考代码

代码非常短。

C 加加版：i 从 n 循环到一，先 push front 放入 i，再把队尾元素 push front 到队首，然后 pop back 删掉队尾。最后依次输出。

## P17｜T5 渗透实验

T5，渗透实验，题号 M 三一五三三。

n 乘 m 的网格，格子总数不超过二十万，一开始全部封闭，然后依次打开 q 个格子。如果存在一条只经过打开格子、从第一行通到第 n 行的四连通路径，就称为已渗透。求第一次渗透发生在第几次操作；始终不渗透，就输出负一。

做法是并查集加两个虚拟结点：TOP 代表整个第一行，BOT 代表整个第 n 行。第一行的格子一打开，就和 TOP 合并；第 n 行的格子和 BOT 合并；再和四个邻居里已经打开的格子合并。

于是，渗透当且仅当 TOP 和 BOT 的根相同。每次操作之后判断一次就行。

如果每次操作都重新 BFS 一遍，是 O q 乘 n m，必然超时。

---

## P18｜T5 参考代码 · C++

C 加加版。fa 数组的大小是 n 乘 m 加二，最后两个位置分别是 TOP 和 BOT。find 用的是路径减半：每走一步，就把 x 的父亲改成祖父。

读入每次操作，行列号先减一转成从零开始，算出一维编号 u，标记为打开。在第一行就和 TOP 合并，在最后一行就和 BOT 合并。再枚举四个方向，邻居在界内并且已经打开，就合并。

每次操作之后，如果 TOP 和 BOT 同根，就输出当前的操作编号，直接结束。循环走完都没有渗透，输出负一。

## P20｜T5 边界：n = 1

这道题有一个边界要单独说：n 等于一。

这时候第一行就是第 n 行，打开任意一格，就同时连上了 TOP 和 BOT，答案是一。参考代码里这两个 if 是各自独立判断的，自然覆盖了这个边界；如果写成 if 加 elif，就错了。

再说一下为什么不用每次 BFS。格子只开不关，连通块只合并、不拆分，这正是并查集擅长的增量连通性。路径减半让每次 find 均摊接近 O 一，q 次操作总共接近线性。

## P21｜T6 括号区间审计

T6，括号区间审计，题号 T 三一五三四，这是最难的一题。

给一个括号串 s，长度不超过二十万；有 q 次询问，q 也不超过二十万，每次问子串 s 从 l 到 r 是不是合法的括号序列。

如果每次都现场扫一遍，是 O n 乘 q，也就是四乘十的十次方，必然超时。

思路是前缀和。令 pre i 等于前 i 个字符中，左括号数减去右括号数。下一页，我们把「合法」写成关于 pre 的两个条件。

---

## P22｜T6 两个条件 + 单调栈

合法括号序列的定义有两条。

第一条，左右括号数相等，用前缀和写出来就是 pre r 等于 pre l 减一。第二条，任意前缀里左括号不少于右括号，写出来就是 pre 在 l 到 r 上的最小值，不小于 pre l 减一。

第二个条件怎么快速判断？用单调栈求出 nxt i，表示 i 右边第一个 pre 比 pre i 小的位置。那么条件二就等价于：第一次跌破 pre l 减一，发生在区间之外，也就是 nxt l 减一大于 r。

单调栈一遍预处理是 O n，之后每次询问 O 一。

另一种做法是用 ST 表，也就是稀疏表，求区间最小值，同样 O 一回答，但要 O n log n 预处理，代码也更长。题目提示的单调栈，就是上面这个更短的做法。
